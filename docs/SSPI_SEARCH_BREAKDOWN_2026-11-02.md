# SSPI 搜索耗时拆解

## 测量范围

源码826a24b，Mac ARM64 Android Emulator独立Engine5，CPU单线程，随机初始化seed 20261103，固定速猪开局root，128次有效模拟。增量与全量分别增加宿主函数计时，不增加native请求。两轮均与已发布基线的完整候选及顺序、先验、Q、访问数、所选动作、模型/FAIR身份、2812推进tick和RPC次数一致；结束snapshotHandles=0。

剖析运行按delta→full串行执行，墙钟为41.017/39.030秒。前一轮无新增计时对照为full 42.505、delta 41.283秒。系统负载未隔离，不能把单轮2.9%差异视作稳定搜索加速；本轮用于归因和计数，而非新速度结论。机器摘要见SSPI_SEARCH_BREAKDOWN_2026-11-02.json，复现脚本见publication/sspi-json-delta-20261102/profile_search.py。

## 新增剖析定位的两个大头

1. MechanicProfileEncoder：delta轮341次，17.727秒，占该轮墙钟43.22%，占模型forward的80.48%。模型forward累计22.027秒。每次都对静态机制目录全部14606条operation、634个profile执行guard/embedding/MLP/pooling。权重和目录在根内冻结，输入仅依赖静态effect_memory；仍被每次根/叶/对手推理重复计算。关系Transformer累计1.815秒，空间编码0.722秒，二者与机制编码同为model内部子项。
2. SSPIInformation.sha256：顶层348次，5.776秒，占该轮墙钟14.08%，解释了此前大部分未分类耗时。SSPILegality.identity把[4,576,5]合法动作Tensor转成嵌套Python布尔列表，semantic_digest逐元素递归并json.dumps。捕获root的离线十次重复测量：legality摘要平均15.022ms，frame 0.344ms，hand 0.084ms。额外cProfile仅用于调用归因，其插桩耗时不当作实际均值。

这两项与原生历史增量传输无关，且目前没有缓存。结论只针对该开局root；中后局实体数量与信念重建成本可能不同。

## 为什么增量对这个搜索根作用小

| 原子捕获指标 | 全量剖析轮 | 增量剖析轮 |
| --- | ---: | ---: |
| 请求数 | 2943 | 2943 |
| 响应bytes | 136139184 | 132435873 |
| 纯JSON解析秒数 | 0.2418 | 0.2290 |
| 完整原子校验秒数 | 0.9565 | 0.9725 |

该搜索根响应只减少2.72%，而非长局诊断的97.57%。2812ticks是128次短分支累计，不是一条持续积累历史的长对局；开局历史少，130次restore又清交付游标，恢复后的首次捕获重新给出保留窗口。当前对象、运行时状态和验证仍完整保留。两种路径同样执行2813个step RPC、2943个原子观测RPC，增量不减少调用次数。

完整长局持续前进，旧事件反复出现，因而增量大幅减少响应。该结果不证明中后局搜索没有收益，也不支持把整局34.2%的局部墙钟改善直接套到搜索根上。

## 后续顺序

优先在冻结推理阶段复用effect/profile编码；用模型身份、device、dtype管理生命周期，权重更新/载入后失效，训练仍保留完整梯度。其次消除同一不可变FAIR信息的重复摘要及合法动作逐布尔序列化，同时保持既有SHA字节协议和必要校验。随后才处理2812次逐tick推进的RPC/观测批量化；必须先验证事件唤醒、预约回执、补牌和快照协议一致，不减少128次有效模拟或搜索时域。

本次只做性能诊断，未实现上述缓存、未更改模型/搜索/战斗语义，未产生训练episode或模型强度结论。原生出牌拒绝与混合完整局验收仍是后续训练的独立阻塞项。
