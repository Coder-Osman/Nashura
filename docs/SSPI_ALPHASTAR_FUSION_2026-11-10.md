# SSPI AlphaStar 式跨分支交融

## 实现内容

本次在保留 FAIR 输入、因果组、组级关系 Transformer、32×18 空间分辨率、结构化动作接口和现有损失的前提下，增加跨分支上下文交融：

- 组级关系 Transformer 输出按 `child_group_index` 回填给每个子实体，经门控残差融合后，同时送入空间 scatter 和候选编码。填充子实体经 mask 清零；没有让最多160个子实体进入全局稠密注意力。
- 场景 token、标量摘要和手牌摘要形成全局决策上下文，用于条件化每个空间残差块的 FiLM。FiLM 零初始化，初始空间残差仍保持 identity 行为。
- 共享512维主干将场景、空间、标量、手牌和候选摘要分别拼接，输入宽度从640扩到768。
- 新增只读取 FAIR 六塔 `TowerSetV4` 行的价值摘要支路，保留塔血、塔型、归属、位置和范围特征；使用 masked mean/max set pooling，对塔行置换不敏感。价值头融合共享表示、塔摘要、标量摘要和手牌摘要。
- 策略头增加彼此独立的标量与手牌投影，再调节 WAIT/PLAY/ABILITY 条件策略 logits。速猪的 ABILITY 合法掩码仍为空。

代码没有添加历史序列、循环网络、对手私有状态或额外启发式答案。MCTS、搜索预算、训练损失、动作及补牌协议均未改动。

## 版本与参数

- 模型架构：`sspi-policy-value.v4`
- Checkpoint：`sspi-mac-pilot-checkpoint.v4`
- 塔血缓存：`sspi-tower-head-cache.v2`，从单一共享向量改为完整1024维价值头输入。
- 当前参数量：8,648,269，低于10M上限；基线7,869,645，增加778,624（约9.9%）。FP32参数存储约从30.02 MiB增至32.99 MiB。
- 旧v3 checkpoint和旧512维预热缓存不做迁移；checkpoint 加载按 schema、架构摘要和严格 state dict 校验拒绝混用。

## 工程验证

主引擎回归：**499 passed in 157.10 s**；公开检查：**1,104 passed, 42 skipped**；gitleaks扫描约42.58 MB，无发现。新增覆盖包括：子实体按组索引读取上下文、padding mask、候选编码接收上下文化实体、六塔集合置换不变与血量/位置敏感、策略损失到实体融合/空间 FiLM/策略头的梯度、价值损失到塔支路/价值头的梯度、合法动作分布和checkpoint往返及旧v3拒绝。

在相同随机种子和 FAIR 测试状态上，单线程 CPU 8次预热后测40次前向：旧/新模型中位数分别10.18/10.80 ms，p95为11.88/12.13 ms。MPS 5次预热后测20次：中位数89.72/95.00 ms，p95为92.58/105.23 ms；新模型 CPU/MPS 有限合法动作 log-prob 最大差 `1.19e-7`，WIN/LOSS logits 最大差 `3.49e-9`。本机 MPS 前向明显慢于 CPU，本轮只做前向核对，没有在 MPS 上训练。

MPS当前分配从36.61增至39.58 MiB，增量与FP32参数增长相符；驱动分配约1.1 GiB包含MPS运行时。隔离进程峰值RSS受PyTorch导入和分配器影响，不用它声称模型节省内存。以上是单状态工程探针，不是吞吐基准、训练验证或模型强度结果。

本轮未运行新采集、MCTS搜索、参数训练、checkpoint训练恢复或胜率评估；这些项目需要用新v4初始化身份另行执行，服务器训练保持既定要求。
