# Nashura：Mac 单机稀疏搜索训练验证规格

> 版本：`sspi-mac-pilot.v1` · 2026-11-01  
> 定位：实施用训练设计，不是已实现、已跑通或已证明有效的训练结果。  
> 代码阅读基准：`Coder-Osman/Nashura main@5da75d6591fd5cf68c168d293a3b8d7078a2d96a`。  
> 唯一计算设备：用户的 Apple M4 Max / 36 GB 统一内存 Mac。不得假定远程 GPU、五机集群或额外服务器可用。  
> 本文取代此前 SSPI v1/v2 中的多架构、多参数量、历史 token、GRU、海量评测与集群部署建议；不修改历史实验事实。

## 1. 本次究竟验证什么

**核心问题：从随机权重开始，少量高预算搜索能否教出更强的无搜索策略？**

锁定一个网络、一副含英雄的卡组、一个原生引擎后端和一套动作时钟。主组在每位玩家真实决策边界独立以 `p=0.05` 搜索，每个搜索根完成 `1024` 次有效 PUCT 模拟；其余决策从冻结策略直接采样。只有搜索根产生策略和终局价值梯度。

只保留一个训练框架对照：`p=0.40, N=128`。两组的名义搜索预算都是 `p*N=51.2` 次模拟/玩家决策，但实际局长、决策频率、树深和推理耗时不同，不能声称严格等墙钟或等原生 tick。没有这个对照，“打赢初始随机策略”只能说明学到了东西，不能说明稀疏深搜优于较密浅搜。

本轮不是论文级结论：一个初始化种子、小规模配对评测；不给跨种子泛化、最优架构、广泛卡组能力或强人类水平作结论。未出现正信号时先报告证据不足，不临时增加网络、辅助损失或无限延长训练。

## 2. 源码审查后的必要修正

| 已观察到的代码事实 | 对本次实施的影响 |
|---|---|
| `fair_final/model.py` 是无持久循环状态的条件策略/WDL网络，但旧动作头是 WAIT/ACT 和31维延迟 | 新版独立动作协议，不能只截取旧 checkpoint 的五个输出 |
| `event_abilities.py` 和技能文档已有精确来源实体、费用、技能身份与执行回执路径 | 复用技能语义；把它真正接入搜索、采集、损失及评测，不能只给网络加一个按钮 |
| `fair_final/native.py` 的 `advance_reservations` 只处理出牌，且防止其他 pending ability 混入 | 现有 FinalRuntime 不是自动支持技能的通用执行器，必须适配 |
| `fair_final/refill_belief.py` 能表达手牌空槽，但检查固定 HOG_DECK，并把逻辑待补牌与物理在手牌分开 | 复用区别而非复用 Hog 假设；逻辑手牌不得直接作为当前可出牌掩码 |
| 部分公开历史、信念构造代码同样固定 Hog 卡组 | 含英雄试验前必须消除本次卡组涉及的硬编码；不能称其已支持任意卡组 |
| `fair_final/learning.py` 的价值损失默认覆盖所有传入行 | 新训练索引必须在两个 loss 之前排除所有 DIRECT 行 |

资料只证明接口/局部代码存在，不证明当前 Mac 已完成英雄真实对局、英雄信念世界或1024根搜索。旧 README 可能落后于用户本地进展；不据此否定本地已完成工作，也不虚构新验收结果。

### 2.1 一副卡组就够，但不能没有英雄

首先复用本地已经通过真实引擎执行的、包含一个无指向主动技能英雄的卡组；固定双方卡组、等级、形态和模式。把实际八张 card ID、技能 ID 与规则版本记录进 `run_config.json`，然后整轮不变。

公开材料未证明哪位英雄已经在当前 Mac 后端完成真实验收，因此本文不杜撰一个“已支持”的英雄或卡牌 ID。若本地没有合格卡组，只挑一个原生 catalog/runtime 标明支持的无指向英雄完成必要测试，再冻结这一副卡组；不做卡组强弱筛选。该事实由实施者读本地资源/回执解决，不另行要求用户设计卡组。

**没有实际英雄技能覆盖时只能报告纯出牌链路诊断通过，不能报告本规格通过。** 不做全英雄、指向技能、所有进化/特殊形态的通用化；已有路径涉及的英雄存活、技能冷却和轮转规则仍必须正确。

## 3. 当前决策状态：没有神经历史，不丢必要状态

网络输入是 `x_t = (当前战场, 己方当前状态, 对手当前信念摘要, 时间/规则, 合法性)`，不是 RGB 截图，也不是对局历史序列。

外部 Tracker 持续消费公开事件，把历史压缩为“现在知道什么”。原始日志可保留用于状态重建与审计，不送入网络。Tracker 确定知道的事实与估计必须分开；未知不等于零，不等于不在手中。

| 输入流 | 必须保留的内容 |
|---|---|
| 战场实体/群体/子单位 | 类型、所有权、位置、速度、血量/护盾、可见目标、攻击/部署阶段、相关冷却、当前可见效果；未知字段有 mask |
| 塔与地图 | 塔血、激活状态、当前攻击阶段；现有合法地图几何与实体空间投射 |
| 己方八卡身份 | 规则属性、`in_hand_ready`、槽位、轮转/可见下一张、已知可用性；牌身份不随手牌空槽重排 |
| 己方四个物理手牌槽 | `occupied`、实际 card ID 或 EMPTY、补牌是否待完成、可获知的剩余时间/顺序及 known mask |
| 己方资源 | 精确圣水、恢复阶段；当前有关的资源预约状态，不重复推断过去动作 |
| 英雄技能 | 当前来源实体、技能身份、费用、冷却、次数/状态、可用性；实体 ID 只用于路由，不作为任意数值特征学习 |
| 对手信息 | 已揭示卡牌、轮转/在手可用性的已知/未知状态，圣水区间；公开可知的英雄技能状态与不确定性 |
| 时间/规则 | 剩余时间、加时/倍率/模式、当前影响动作结果的规则阶段 |
| 动作掩码 | 同一根上的模式、卡牌、位置、延迟、技能来源合法性 |

禁止：真实对手未公开手牌/牌序、私有资源真值、对手尚未公开预约、真实比赛 RNG 状态、native audit digest、对手本次搜索结果。

尽量沿用既有 FAIR 张量定义，不为了“必要信息”直接开放原生内存字段。自己的补牌到达时刻等字段若只能从引擎私有实现读到且不属于约定 FAIR 输入，只能使用公开规则推断并标注 known，或保持未知；不能假称单帧可观察。

### 3.1 删除 previous_action，但保留未完成动作的真实影响

上一动作已经发生的结果由当前单位、资源和卡牌状态表示，不再单独编码“上次选了什么”。

本版在**己方预约已经执行、取消、被事件打断或到期后的决策边界**调用模型，故该玩家本人的未决预约应为空；已有 native 部署/技能动画仍作为当前物理状态。若某适配器允许预约未结算就重新决策，必须先规范化为相同边界，不能删除预约信息后继续用不完整状态决策。

整个 AI 系统仍有 Tracker、计时器和快照状态；“无状态模型”不代表系统不需要状态恢复，也不保证这个紧凑摘要是数学上完全充分的 belief state。

## 4. 不足四张手牌与英雄轮转：必须明确的语义

### 4.1 三种东西不能混为一谈

- **实际就绪手牌**：native 当前手牌槽中确实存在、可以按规则提交的牌。
- **下一张/待补牌**：已知身份或顺序，但尚未进入可用手牌槽；不能出。
- **静态八卡身份集合**：卡组的身份目录，不表示八张牌当前都在轮转队列里。

例如 `hand_slots=[A, EMPTY, C, EMPTY]`，下一张 B 已知、随后 D 在排队：此时只有 A、C 可成为 PLAY 选择；B、D 可以影响决策和价值，但不应因“下一张可见”被当成在手牌。

### 4.2 最小数据表示

固定八个卡牌 token 表示卡身份；四槽描述表示物理占用。不把手牌强行补齐四张，不复制最近一张牌，不用零 ID 充当真实卡，不按紧凑数组下标替代 native handIndex。

每个槽至少有 `occupied, card_id_or_empty, refill_pending, refill_remaining_ticks, refill_time_known`。有多个待补牌时保留原生队列顺序/可知信息；必要时以最多四个小记录表示，不引入历史 Transformer。下一张牌提供 `card_id, identity_known, available_now=false`，实际到位后才更新 readiness。

**本版不支持“现在预选一张还未到手的牌，等它补出来自动打”。** 这不是新规则，只是本次控制器的简化动作边界：PLAY 根候选必须现在在手，允许等待五档中的合法时刻支付；补牌到达后唤醒并重新决策。不得把未来到手当作当前合法。

### 4.3 由原生引擎维护补牌，控制器不补牌

补牌周期、阶段转换和排队截止由真实引擎决定。旧材料中的20/10/7 tick是特定模式的历史观测，不能硬编码为所有模式/英雄的通用规律。计时特征必须使用当前绑定规则与已验证的事件定义，阶段切换是否追溯改变已排队补牌也以引擎为准。

己方手牌从2→3→4张时，外部状态、合法掩码、缓存和策略决策同步更新。等待期间即使没有敌方出牌，也必须在本方补牌到位时获得决策机会；不需要重新固定每帧推理。

### 4.4 英雄可能使普通八卡轮转假设不成立

不要直接沿用 Hog 的 `len(hand)+len(cycle)==8` 或统一“出四张就回来”断言。英雄存活/回场及模式规则可能改变其轮转资格，应由原生队列和已验证事件维护。

需要守恒的是**卡身份及原生状态解释的一致性**，不是硬凑一个普通卡组队列长度。英雄本体、技能来源、手牌中的英雄牌不是同一个对象。一个已在场实体并不普遍代表其来源卡已离开轮转；只对原生明确规定的英雄状态作相应处理。

Tracker、belief世界构造、动作掩码、快照恢复必须使用同一规则。只修补真实对局的手牌显示而让搜索仍即时补满四张，属于正确性失败。

## 5. 固定模型：复用约10M级骨干，不再比较架构

为减少实现成本，本版选择现有 V4/`fair_final` 路线的固定规格，而不是再实现前稿的192维双向融合新网络。参数量以用户现有约10M为参考，不增加大LSTM，也不为了凑到精确10,000,000而填充无用参数。

**固定规格如下；最终只统计一次实际参数量和各模块占比，不做5M/10M/20M扫描。** 新字段/技能头可能改变精确参数量，未经实例化不声称其恰好等于10M。

| 模块 | 固定规格 |
|---|---|
| 卡牌/机制语义 | 复用规则表和128维语义编码；所有可学习参数重新随机初始化 |
| 子单位编码 | 128维；群体内4个学习池化槽；保留精确子单位位置进入空间分支 |
| 实体关系网络 | `d_model=256, layers=4, heads=8, FFN=1024`，沿用相对几何/关系偏置 |
| 实体容量 | 己方8卡、对手≤9行（含未知汇总）、6塔、≤48群体、≤160子单位；溢出按现有显式规则处理，不能静默漏掉技能来源 |
| 空间网络 | `[B,64,32,18]`；现有 scatter + 3个标准空间残差块，不做卷积种类/层数对照 |
| 标量/槽位状态 | 当前规则/资源/补牌/Tracker摘要编码为128维；四槽小特征先池化，不是历史编码 |
| 候选摘要 | 128维，包含实际在手牌及原生技能候选；不将搜索随机候选表当作状态特征 |
| 全局融合 | `scene256 + spatial128 + scalar128 + candidate128 = 640` →512；2个512维残差MLP + LayerNorm |
| 模式头 | 512→256→3：WAIT、PLAY、ABILITY |
| 卡牌头 | 全局query与己方8卡token匹配，按当前合法在手身份mask |
| 位置头 | 卡牌条件化query与576个空间key匹配，key宽128，按该牌位置mask |
| 出牌延迟头 | `[h512, card256, selected_cell128]`→256→5 |
| 技能来源头 | `[来源实体表示, 技能语义, 当前费用/冷却/次数]`→256；全局query作masked pointer |
| 价值头 | 512→256→3：WIN、DRAW、LOSS，`V=P(WIN)-P(LOSS)` |
| 删除 | EventSetEncoder、PreviousActionEncoder、任何持续RNN、历史tokens、额外辅助预测头 |

推理顺序：当前状态一次编码 → 三模式分布 → 条件选择。不要为每张卡或每个格点重跑CNN。空间key、卡语义和状态编码仅在冻结模型/相同输入/mask身份下缓存；权重更新、补牌、冷却变化或快照恢复后的新输入必须使不适用缓存失效。训练时禁止复用旧权重下的特征缓存。

输入字段宽度改变应使用独立版本配置，不原地破坏 `ModelConfigV4` 对历史schema的固定检查。

## 6. 动作协议：技能不是第九张牌

完整动作是带标签的联合类型：

```text
WAIT()
PLAY(card_id, cell, delay_index)          # delay_index = 0..4
ABILITY(source_entity_id, ability_id)    # 当前支持的无指向技能
```

概率定义：

```text
P(WAIT) = P(mode=WAIT)
P(PLAY,c,x,d) = P(mode=PLAY) * P(c|PLAY,x_t) * P(x|c,x_t) * P(d|c,x,x_t)
P(ABILITY,u,k) = P(mode=ABILITY) * P((u,k)|ABILITY,x_t)
```

这里 `x_t` 是当前状态，`x` 是格点；技能指针指向确切 `(source_entity, ability_id)` 候选。技能不虚构卡牌、位置或延迟概率。无合法技能时屏蔽 ABILITY；无合法出牌时屏蔽 PLAY；WAIT始终提供安全合法分支。所有条件空集应在上一级mask掉，不能对全负无穷 logits做softmax。

- **PLAY**：延迟 `200*(index+1)ms`；50ms/tick下为4/8/12/16/20 ticks。提交到native时核对最终执行tick，避免队列包装层再多加一tick。
- **ABILITY**：复用既有下一原生tick执行语义，仅当前可用且费用足够的来源；不新建技能延迟头，不误称“0ms为第六档出牌延迟”。
- **WAIT**：最长20tick；公开部署/已确认公开技能事件、本方补牌到位、本方技能可用性发生变化及已有到期事件可按版本化规则提前唤醒。不对每次HP变化或每个物理tick唤醒。

同tick双方先冻结各自信息、各自选择，再原子提交；不能一方搜完并提交后让另一方看到其未公开选择。

### 6.1 技能提交和回执

来源必须是本方实际在场英雄/原生能力控制器，不使用卡组位置猜来源。提交前检查来源存活、技能ID一致、费用、冷却和次数；执行后以 `action_executed` 中确切来源/技能身份及扣费证据确认，不把 queued当作executed。

决策后来源死亡、技能被打断等**规则允许的失败**应被表示为动作结算结果，并在搜索与真实对局中一致处理，不偷偷重定向到另一个同类英雄。身份错配、重复扣费、无法核对回执属于协议失败，停止并隔离该局。

旧技能PPO文档的“取消行排除学习”不能机械移植：本实验监督的是当时合法的完整决策。自然的预占/取消可以保留其搜索标签和真实终局；协议错误不能保留。二者要分类记录，不能只训练成功执行或赢方的动作。

动作存储使用带类型和稳定身份的key，例如 `play:<card>:<cell>:<delay-index>` 与 `ability:<entity>:<ability-id>`。原先23041仅是WAIT+纯出牌ID上界，不再把它当作含技能的完整固定动作空间。

## 7. 稀疏搜索、自博弈和教师目标

### 7.1 一步的定义

“步”是某位玩家一次真实决策边界，不是物理帧、不只是成功出牌。技能/补牌唤醒形成的新决策也进入同一门控。双方各用独立门控RNG，以 `(run, arm, game, owner, decision_index)` 绑定；不按胜负、技能可用性、手牌数量或模型熵挑搜索点。

`p`是期望比例，不强行每局凑5%。即使一次根只有WAIT合法，也不悄悄改变门控统计；可利用正确缓存降低开销，但不能伪造1024有效访问。

### 7.2 每代收集权重冻结

主组 `SEARCH1024` / 对照 `SEARCH128`：用当前冻结网络提供先验与叶WDL，执行访问分布采样。DIRECT：完整联合策略采样，温度1。两类行为都真实执行并改变同一条对局轨迹。

同一局/同一代不热换网络。双方从同一代自博弈起步；不引入历史1755教师、专家开局、PPO轨迹或额外对手联赛。记录对局结果前不发布可训练样本。

### 7.3 固定搜索规格

| 参数 | 固定值 |
|---|---|
| 算法 | PUCT；`c_puct=1.5` |
| 搜索根预算 | 主1024，对照128；只计完成有效边并回传的模拟 |
| 候选上限 | 32，初始开放至少8或全部强制覆盖项 |
| 强制覆盖 | WAIT、每个合法在手牌至少一个动作、每个当前合法技能来源/技能至少一个动作 |
| 其他候选 | 沿用位置峰、延迟邻居、完整联合概率采样；去重；不把真实隐藏状态用于提案 |
| 探索 | 根非WAIT分支噪声比例0.25、Dirichlet总浓度10；两组同规则；保留原始与搜索先验 |
| 行为/标签 | 温度1；`pi_search(a)=N(a)/sum_b N(b)`，不锐化标签 |
| 深度/时域 | 复用completed-boundary约束：软6个同时提交边界组/200ticks，必要时最多再6组/60ticks完成当前边；未完成边不回传 |
| 信念 | 每搜索根一个独立兼容世界；本次不做1/4/8世界扫描 |
| 模拟中的对手 | 冻结策略基于其合法信息采样；不递归嵌套完整MCTS |
| 下一实际根 | 新建搜索统计；不做跨根复杂树复用 |

技能不能只是“模型能输出但候选搜索永远不含”。候选和初始开放顺序必须保留上述强制覆盖项，并在有预算时确保这些项得到合法探索；两组使用相同规则。32不是穷尽完整动作空间，1024也不代表看到全部落点。

单信念世界是本次节省工程量的近似，可能过拟合错误隐藏状态；本文不声称解决了信息集搜索或求得Nash策略。禁止为简化世界构造复制真实对手隐藏手牌。英雄技能、牌库/补牌与公开历史必须能在该兼容世界中合法解释；未做到则不能进入主训练。

### 7.4 只使用搜索根的两个loss

自然终局后，对每个验收搜索根按根玩家视角回填 `z in {WIN,DRAW,LOSS}`：

```text
L_policy = mean_roots[- sum_a (N_root(a)/N_budget) * log pi_theta(a | x_root)]
L_value  = mean_roots[- log WDL_theta(z_root | x_root)]
L        = L_policy + L_value
```

网络概率在**完整合法条件动作空间**归一化，不只在32个搜索候选上归一化。PLAY包含卡、格点、五档延迟；ABILITY只包含模式与来源指针；WAIT只包含模式。

**DIRECT行既不进入策略loss，也不进入价值loss、辅助loss或PPO。** 失败、截断、预算不足的根不能贴成完整标签；超时不是平局。本次为简化失败处理，搜索预算不完整或协议错误就中止并隔离整局，不自动用DIRECT补缺后继续发布训练样本。所有成功完成且自然终局的对局（包括输和平）按相同规则接受，另外报告隔离率，防止幸存者偏差被隐藏。

## 8. 优化、回放和随机冷启动

固定 `AdamW(lr=1e-4, weight_decay=1e-4)`；梯度裁剪1；有效batch128，默认microbatch4、累计32次。微批可因内存调整，累计维持同一有效batch；这不是架构实验。

所有可学习权重随机初始化、优化器/replay全新，规则表与静态语义不属于预训练。WDL末层用小随机权重、零bias，初始接近中性但不伪装为校准胜率。LayerNorm/现有规范化保留，新增dropout、奖励塑形、价值热身和辅助头本轮不启用。

终局价值按胜负平学习，不按“每个决策”折扣，避免更频繁技能/补牌唤醒改变同一物理时间的奖励定义。

本轮最多保留三代搜索根，CPU/磁盘存储，按完整对局分组。每代新有效训练根最多提供两次样本曝光额度；**每条根整个本轮最多被训练两次**，旧根不因进入新一代自动重置曝光。优先均衡选择尚有额度的对局，局内无放回轮转；不足一个有效batch的余额结转，不无限复用小集合凑更新。

train/validation/test以整局及配对种子组划分，双方同局不跨分区。无需扫描所有历史实验的全部seed；至少保证本次初始诊断、两组采集、验证及最终评测按清单隔离，重跑不重复计入数据。

随机WDL可能让1024次模拟稳定放大错误估值，全部draw也可能令学习停滞。记录自然胜/平/负、根Q/访问熵、终局叶比例和实际前瞻游戏时长。没有学习信号时诚实归类为冷启动/标签质量瓶颈，不临时加载旧模型或把95%直出步加入训练。

## 9. Mac 单机部署与成本边界

### 9.1 拓扑固定，不做并发扫描

```text
Mac 宿主：单个 Python 调度/推理/训练进程，PyTorch MPS（通过检查后）
    ↕ 复用已有本机通信协议
本机已可用 ARM64 引擎环境：一局真实比赛 + 按需信念分支
```

复用用户现有可运行的 ARM64 Linux guest/原生引擎闭包，不为本实验重新推进Binder清理、macOS原生移植或重写战斗引擎。ARM64指令集相同不代表Android ELF `.so`可以不做运行时适配直接由macOS加载。

默认一个实际对局actor；最多保留双方各一个信念引擎，即最多三个独占引擎会话。内存不足时复用一个按需重建的信念会话，保持相同信息和搜索语义；不增加并发寻找极限。若既有后端必须独占slot0进行全局快照，不混用其槽位。

训练与采集串行分阶段；训练阶段不继续跑自博弈，推理使用冻结模型。不要在没有GPU透传证据的Linux虚拟机里假定能用宿主MPS；MPS模型在macOS宿主运行。[S8]

### 9.2 内存与后端

36GB是CPU、GPU、虚拟机和系统共用的容量，不是36GB显存另加36GB RAM。初始把整体实验工作集目标控制在约24GiB以内并保留系统余量；这是运行策略而非内存实测保证。虚拟机、模型激活、replay和native snapshots都计入。出现持续新增swap或内存压力警告即停止发新局、保存检查点，不能靠关闭MPS内存保护硬撑。[S9]

FP32先跑通，不做量化、CUDA Graph、`torch.compile`或混合精度专项。启动时检查 `torch.backends.mps.is_available()`，真实跑一次包含scatter/attention/技能mask的前向反向。CPU可作为数值参考和显式后备；不默认开启静默CPU fallback，使用后备必须记录并重新估算成本。[S8][S9]

单个1024根可能很慢，所以先测真实根而不是承诺吞吐。测量只需固定几类代表根，不做大规模benchmark：常规根、2/3张手牌根、技能可用根；记录完整根耗时、有效模拟、native tick、推理时间和峰值内存。

### 9.3 预算是停止条件，不是承诺

默认总活动预算8小时：每训练臂最多3小时，其余最多2小时用于一次性检查和独立无搜索评测。实施开始前可整体调一次预算并记录，不能因为中途胜率不理想不断延长。未实际测量前不保证能跑完三代或最终评测。

用首批完整局测出的决策数D和根耗时T估算：`T_game ≈ T_direct_game + p*D*T_search + tracker/belief额外成本`。D包含双方真实决策。若预算明显不支持最低闭环，报告计算预算不足；不要把1024改成128、把只跑一根冒充完整训练或默默购买远程算力。

不在预算不足时切断游戏后当作平局。正常预算停止于完整局/完整更新边界；安全故障中断的局独立隔离。启动下一局前依据已有耗时判断剩余预算是否足够。

## 10. 最小检查：仅保留能防止结论失真的项目

不重新做五机预检、全库数千项回归、全英雄矩阵或多平台性能竞赛作为本实验启动的必要条件。复用已有通过证据，新增/受影响路径做少量参数化测试；真实引擎证据不能由fixture替代。

| 必要检查 | 最小覆盖与通过条件 |
|---|---|
| 动作与概率 | 五档映射4/8/12/16/20ticks；三模式条件概率和为1；无技能/无牌时无NaN；技能无虚假位置/延迟loss |
| 技能真实语义 | 一种本次英雄技能实际执行并扣费；无英雄、冷却、费用不足、来源死亡不能错误执行；核对来源及技能ID |
| 手牌/补牌 | 真实出现3张和2张在手、至少一次多个空槽顺序补入；下一张未到不能出；槽位和牌身份不会串位 |
| 英雄轮转 | 在场/消失与native hand/cycle对应；不沿用Hog八卡守恒断言 |
| 快照A/B/A | 一般根及技能/补牌关键根恢复native+Tracker+队列+冷却+RNG，重放相同动作回到相同合法状态/回执 |
| 搜索 | 至少一个真实完整1024根；技能/补牌状态能走合法模拟；有效访问总和恰为N，未完成边不回传 |
| 训练过滤 | 有搜索与DIRECT混合的真实完整局；仅搜索行参与两个loss；actor冻结；终局视角正确 |
| 更新/恢复 | 一次非零梯度更新与checkpoint读回；RNG/样本额度/优化器状态完整；MPS数值以预先记录容差验证，不要求跨后端bitwise相同 |

能够在少量同一批真实轨迹中覆盖这些场景即可，不为每项另建大采集项目。技能/低手牌状态的定向诊断可以用脚本引导，但该类fixture/定向轨迹不进入主训练、不冒充随机门控的数据分布。

**关键失败就定位并修复这一条，不通过减少校验、读对手隐藏状态或补造卡牌绕过。** 公开源代码中的能力文档本来就区分了脚本桥接测试与真实英雄对局，实施也必须这样区分。[S2]

## 11. 最小有效性实验，不再做多模型矩阵

### 11.1 一个主实验、一个对照

| 组别 | 网络/初始参数 | p | 每根N | 作用 |
|---|---|---:|---:|---|
| A | 本文固定网络，共用保存的theta0，独立新AdamW | 0.05 | 1024 | 待验证框架 |
| B | 完全相同网络与theta0，独立新AdamW | 0.40 | 128 | 唯一较密浅搜对照 |

两组同卡组、规则、Tracker、动作时钟、候选生成、噪声、深度、loss和每根曝光上限。每代使用同一组环境开局种子配对组织，但轨迹分叉后不会相同。两个模型的后续数据必须各自on-policy生成，不能共享A的搜索标签冒充B的自博弈。

只用一个初始化seed `20261101`。不做不同模型大小/层数/历史输入/多信念粒子对照，不用大规模预训练，不采用多代晋级淘汰或自适应调参。

### 11.2 有界运行流程

1. 一次性完成第10节检查，包括一局真实完整混合轨迹；诊断数据单独归档。
2. 保存theta0；A/B交替按代运行，禁止同时占满本机。每臂最多三代，每代目标16局训练+4局验证；按完整局预分配，验证行永不用于更新。
3. 收集一代后，按新根数量和两次曝光额度进行有限更新；不硬凑固定几百个optimizer step。验证只用于监控，最终选用预定的最后完整代checkpoint，不按最低验证CE或反复对战挑赢家。
4. 本轮不做每代400/2000局晋级。主实验跑不出有效样本或完全不能更新时，先结束功能诊断，不继续花费完整B预算。
5. 最终评测两场对阵：A最终 vs theta0；A最终 vs B最终。每场32个独立种子、每种子换边两局，共64局；两场合计128局，全部关闭MCTS。
6. 评测统一完整联合策略采样、温度1、固定独立行为RNG、无根噪声；不要一方逐级贪心一方采样。若今后部署要用greedy，可另行研究；本轮不再增加解码实验。

上述局数是预算内目标上限，不保证Mac能完成。为避免一个臂先跑完另一个只完成一代仍强行比较，优先保持A/B完成同样的代数/局数；未匹配时报告范围差异，不给等预算优越性结论。两组每行曝光相同但训练行数/更新数可能不同，这是搜索标签密度差异的一部分，应如实计入整体成本。

### 11.3 最终只回答三件事

- **工程有效**：真实完整局、技能/补牌正确、1024有效根、搜索行梯度及断点恢复形成闭环。
- **有学习信号**：A的无搜索策略对theta0得分提高，不仅是CE降低。
- **相对框架信号**：在实际成本明确报告的前提下，A对B的无搜索得分有优势。

得分率 `(win+0.5*draw)/games`；以完整换边种子对为重采样单元给出配对bootstrap 95%区间，种子数在评测前固定。区间覆盖50%就写“本次样本不足以区分”；64局和单初始化seed即使有优势，也只是pilot信号，不是广泛有效性证明。

只赢theta0而不赢B：学到了，但尚未证明稀疏深搜的相对收益。二者都不赢但工程正确：框架效果未获得支持；检查随机价值、教师质量、样本数，不立即归咎10M容量。没有完成足够自然终局：只给工程/预算结果，不给学习失败结论。

## 12. 足够用的产物与实施顺序

复用现有模块，只新增一个小型 `training/sspi_mac/` 实验包；不要照前稿把所有组件拆成十几个新框架文件。可按 `config/model/actions/collector/learner/evaluate` 六个职责组织；能稳定复用的底层接口直接引用，改协议的部分有独立版本。

建议实施顺序：**动作/补牌适配 → 快照和单根搜索 → 固定模型与只搜根loss → 单局闭环 → 两臂小试验**。不要先做大dashboard、分布式服务、自动调参或长期任务系统。

只要求这些产物：

```text
runs/<run-id>/
  run_config.json          # 源代码、规则、动作、模型、卡组、seed、设备与预算
  initialization.pt       # 全新theta0，不提交公开仓库
  episodes/               # 完整局结果、轻量动作账本、搜索根输入/访问/终局标签
  checkpoints/            # 每代末模型、优化器、RNG、replay游标/曝光账本
  metrics.jsonl           # 代际、实际成本、搜索/技能/补牌/学习指标
  evaluation.json         # 固定配对评测全部胜平负与区间
  report.md               # 结果或明确的未完成/失败边界
```

日志指标控制为：有效局/搜索根、门控实际比例、完整模拟数、自然胜平负、PLAY/ABILITY/WAIT次数、2/3张手牌出现及补牌次数、合法规则取消/协议错误、policy/value验证损失、根耗时/原生tick/推理时间、内存与样本曝光。异常根保留详细现场；不为每个正常native tick写巨量JSON或重复全历史哈希。

checkpoint原子保存后读回；收集权重固定，恢复验证模型/动作/规则版本。正常stop于完整局或optimizer step边界。拒绝旧10档/31档/纯出牌schema混入，不擅自覆盖历史部署和实验目录。

## 13. 本次刻意不做的工作

不测5M/10M/20M，不比较192/256维，不训练LSTM，不加历史tokens，不试所有英雄/卡组，不改战斗逻辑，不重新追求零Binder，不做集群/并发扩展，不要求400+2000局晋级，不做多seed正式统计，不引入价值预训练/辅助奖励/专家数据，不建立复杂自动审批式验收流水线。

保留正确性的底线不是繁琐工作：真实动作、技能身份、补牌空槽、FAIR信息、快照恢复、1024有效预算、搜索行训练以及完整终局。这些错误会直接使实验回答另一个问题，不能省略。
