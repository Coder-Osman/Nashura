# SSPI 每代追加直出价值头训练

## 目的与边界

保留现有 SSPI 网络、FAIR 输入、WAIT/PLAY/ABILITY 接口、延迟补牌、5%×128 搜索采集和搜索根联合更新。每代完成原更新后，追加一批双方完全直出的自博弈，单独更新现有 WIN/LOSS 价值头，然后保存该代最终 checkpoint，供评测和下一代使用。

这与 KataGo 的随机搜索预算在动机上相近，但不是 KataGo 的复现：KataGo 的快步仍做少量搜索，我们的普通步完全直出。追加阶段进一步针对本代直出策略的终局价值提供监督。参考：David J. Wu, *Accelerating Self-Play Learning in Go*, arXiv:1902.10565，§3.1。

本次交付仅为代码、工程测试与协议文档；没有启动新实验，没有调用、重启或重配 AVD、adb 或原生引擎。旧三分类实验、独立 value-only 实验和历史 checkpoint 保持原身份。

## 每代顺序

1. 使用上一代最终 checkpoint 冻结采集原 SSPI 搜索训练／验证对局。
2. 执行原来的搜索根策略 CE + 终局 WIN/LOSS CE 更新及稳定性验收。
3. 冻结更新后的整套策略，采集显式配置数量的直出训练局和独立直出验证局。双方始终从合法联合策略采样，0 SEARCH，不创建搜索世界或派生搜索样本。
4. 沿用现有 value-only 采集协议，每位玩家的每个真实决策独立以50%选为价值监督点。采样只影响记录，不增加观测或决策；包含只能 WAIT 的状态。终局后按玩家视角生成 WIN/LOSS 标签。
5. 只训练 `value_head`，其余参数全部冻结，模型保持 eval 模式以保护共享缓冲区。确定性打乱，每个训练状态最多使用一次；batch128、microbatch4，AdamW lr1e-4、weight_decay1e-4、梯度裁剪1。
6. 每32步和轮末验证，保留验证 CE 最好的模型与优化器状态。没有改善则回滚追加更新，记录 `rolled_back`；没有有效训练／验证状态则 `skipped`。原 SSPI 更新继续保留，这些状态不算追加阶段学习成功。
7. 保存最终代际 checkpoint，并恢复验证模型和完整 AdamW 状态；后续无搜索评测与下一代搜索使用这个最终 checkpoint。

策略头参数冻结还不够：共享 encoder、hand projection、trunk 也必须冻结。现有独立 value-only 实验仍保留“共享层+价值头更新”的旧定义；新阶段通过独立 `head_only=True` 路径实现，不改变该实验。

## 显式启用与版本身份

在**新运行**的 `run_config.json` 中登记：

```json
"direct_value_stage": {
  "schema": "sspi-direct-value-stage.v1",
  "train_games": 8,
  "validation_games": 4
}
```

8+4仅为配置格式示例，不表示已经确定或启动这组实验；两个局数均须显式指定为正整数。缺少该字段的历史运行完全保持原流程。开始后不得增删此阶段或修改局数；后续代际和评测核对父代配置，变更需要新的运行身份。

模型架构及二分类 checkpoint/episode 版本保持不变。每代 checkpoint 身份增加独立阶段结果、阶段 schema、计划、模型 SHA、优化器 SHA、源码 SHA、引擎身份及数据文件校验和，避免与仅 SSPI 的历史结果混淆。

追加数据位于 `direct-value/generation-NNNN/episodes/`；阶段 run_id 独立于原搜索数据，并带代际号。原搜索 DIRECT 决策仍不参与原来的损失；只有新追加数据参与追加价值损失。

自然平局整局排除，保留终局和排除计数，不补采；失败、截断和 quarantine 不产生标签，也不当作平局。已有不完整或隔离输出要求检查，自动流程不会覆盖或重复采集它。

## 优化器与中断恢复

追加阶段优化器只包含价值头参数，沿用原 SSPI AdamW 中该头的动量；验收后仅将该头的最优动量写回主优化器，共享层和策略分支的动量保持原样。最终 checkpoint 保存完整优化器，接受的追加步数与原搜索更新次数分开记录，并计入累计 optimizer_steps。

阶段 `plan.json` 固定输入模型、输入优化器、源代码、引擎、计划和随机种子。进程锁防止同阶段同时运行两个采集器。完整 episode 可复用但必须通过身份与文件校验。

阶段 checkpoint 保存最优状态及完整结果记录。重试时，在原搜索更新产生相同输入状态的前提下，恢复已经完成的阶段，不再采集或重复更新；即使 checkpoint 保存后、`result.json` 写入前中断，也可从 checkpoint 中恢复结果。输入状态、源码或证据变化时拒绝自动续跑。

## 验证与报告

检查所有非价值头参数和缓冲区的 SHA；CPU 合成 FAIR 固定输入上的所有合法联合动作 log-prob 逐位一致，价值头产生非零更新。MPS 参数 SHA 同样保持一致；实测推理存在2.38e-7至4.77e-7量级 log-prob 末位差异。只执行价值前向而不执行optimizer.step的对照也复现4.77e-7差异。MPS专项采用绝对1e-6容差，不将其描述为逐位相同。正式阶段仍沿用当前CPU执行协议。

报告独立直出验证的 WIN/LOSS CE、Brier、ECE10，以及训练集频率常数基线和按完整对局bootstrap的CE差值。保留原搜索验证指标；它们描述追加阶段开始之前的搜索联合更新，追加阶段的指标单独记录。

同一价值头仍先接受混合搜索策略的终局监督，再接受当前直出策略的终局监督；最后一个阶段是有意让价值更贴近直出策略，而不是同时预测两个不同策略的价值。是否改善下一代搜索、最终直出胜率，以及冻结表征是否足够，均需要后续原生完整对局验证。

工程测试使用合成输入和合成episode，不作为原生对局、完整训练或强度证据。具体发布检查结果见 `SSPI_DIRECT_VALUE_VALIDATION_2026-11-03.json`。
