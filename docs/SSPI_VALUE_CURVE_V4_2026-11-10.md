# v4 直出纯价值头样本效率试验

## 目标与固定协议

本实验测量：从全新随机初始化开始，固定直出策略需要多少自然终局数据，才能让价值预测在独立对局上稳定优于随机初始模型和训练集胜负频率常数基线。结果只评价WIN/LOSS预测，不解释为策略强度或胜率变化。

- 架构固定为 `sspi-policy-value.v4`，初始化seed `20261103`。不加载旧checkpoint、优化器或历史对局。
- 采集actor始终是随机初始模型，使用CPU直出；所有真实动作均为DIRECT，MCTS搜索概率为0。
- 每位玩家每个真实决策点独立以 `p=0.5` 采样价值状态，包含WAIT决策。只在完整自然胜负终局后附加该玩家视角的WIN/LOSS标签。
- 训练时只更新价值头262,914个参数；共享主体、策略头及缓冲区冻结。每个新训练状态只使用一次，batch 128、microbatch 4、AdamW `lr=1e-4`、`weight_decay=1e-4`、梯度裁剪1；AdamW状态跨检查点恢复。
- 每新增64个训练对局检查一次，最多1,024个训练对局；固定另采32局验证及32局最终留出。训练、验证和留出使用不相交的随机种子域。
- 每个检查点记录WL CE、Brier、ECE10，并与初始模型和基于训练样本真实胜负频率的常数基线比较。CE差异按完整对局聚合并配对bootstrap；16个检查点×2个比较使用Bonferroni校正，总family-wise alpha为0.05。
- 首次验证集同时显著优于两项基线时停止新增训练局，并用固定最终留出只评一次；否则继续至1,024局。自然平局整局排除、不补采；失败或截断局隔离，不作标签。
- 采集使用macOS宿主上的既有ARM64 Android Emulator原生引擎；价值更新使用单张远端CUDA GPU，不用MPS。不会为本实验启动VMware。

## 自动收尾

`tools/finalize_value_curve.py`只读取既有episode、checkpoint和最终评估记录，不重新采集、训练或评估。`--preview`已用当前128局检查点实际运行，通过模型/AdamW身份、冻结函数SHA、原始episode和动作账本校验，输出私有预览。

正式收尾使用`--wait`等待协调器完成；`--publish`在复核起始Git提交及工作区干净后，生成脱敏摘要，依次执行主工程、公开检查、快照检查和gitleaks，再提交并正常推送main，核对远端HEAD。发布过程使用独占锁；若训练失败、发现未提交工作、证据不一致、检查失败或推送被拒，则保存`finalizer_status.json`及日志并停止发布，保留现有数据和代码供检查。不会强推或自行重写历史。

## 运行修复与恢复边界

首次远端加载在任何训练更新之前因Mac checkpoint携带MPS随机流而失败。现支持跨CPU/CUDA宿主加载：保留Python、CPU及当前可用后端的随机流恢复，跳过当前宿主不存在的加速器随机流；可用CUDA设备数量仍严格校验。旧初始checkpoint `2916db10ae30ba9155df87998d9ac0d18ea124b5c5a1f3167647e453a9e7ebc6` 和配置已归档，当前初始checkpoint只更新恢复身份，模型参数SHA保持不变。实际采集使用CPU、训练使用CUDA，没有MPS训练。

首批正式CUDA更新保存模型与优化器后，旧协调器结果字典发生重复字段异常。已从保存的64局checkpoint、130步AdamW、原episode SHA、动作账本、曝光摘要与验证特征缓存重建结果，重复优化步为0。该次未落盘的最大梯度范数字段保留为null，没有推定数值。后续协调器先把完整检查摘要嵌入checkpoint，再写JSON与提升current；新增故障注入测试确保中途退出后只补全记录，不重新训练同一批状态。

冻结主干的编码支持批量128状态缓存，正式训练仍为batch128/microbatch4；缓存与完整前向首批抽查要求atol1e-6、rtol1e-5。真实222状态诊断得到1024维缓存，编码1.027秒，最大logit误差4.657e-9，冻结函数SHA一致。该诊断与另一编码任务同时运行，只作为正确性和实测耗时记录，不作为隔离的速度提升比例。

首批64局及32验证局保持原collector源码身份；第65局起和最终留出显式绑定新源码修订。初始checkpoint身份、模型权重和AdamW连续性均保留；不改写已完成episode身份。服务器NVML探测有版本警告，但PyTorch CUDA分配、两步预检和本次130步正式更新均实际成功，没有修改驱动或干预其他任务。
