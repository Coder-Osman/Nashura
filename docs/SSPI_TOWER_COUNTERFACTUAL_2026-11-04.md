# 塔血启发式两阶段数据扩增

本实验是独立的塔血拟合诊断，不更新 SSPI 搜索策略，也不采集新对局。输入来自先前九个已完成的训练来源：原始 32 局及后续八批各 32 局，共 288 局完整自然胜负对局。失败的第九批和先前用于评估的旧留出局未进入来源清单。原始 episode、动作账本、FAIR 摘要及模型身份逐局核对；扩增只保存塔血差异和目标，不复制完整 FAIR 张量。

## 固定协议

- 先按完整对局和固定随机种子切成训练 230、验证 29、留出 29 局，再生成任何变体。训练来源有 61,296 个状态，验证来源有 7,445 个状态；同一来源局的所有变体保持在同一划分。留出来源只记录身份，最终推理时才读取和生成变体。
- 合成阶段分别从训练和验证局抽取八个无部队、效果和事件的场景模板；在全部 729 种六塔损伤组合和 41 个塔血差档上生成各 29,889 个样本。所有合成塔保持存活，未激活的国王塔不虚构受伤。
- 真实上下文阶段每个来源状态有四个版本：原状态和三个固定种子的反事实塔血版本。仅同步修改塔血比例和绝对归一化输入；已摧毁塔维持零血，存活塔维持正血，其他 FAIR 字段逐位保留。
- 目标为己方视角的 `(己方总塔血-敌方总塔血)/(双方总塔血)`，WIN/LOSS 软标签分别为 `(1+目标)/2` 与 `1-该值`。每阶段最多八轮，按完整训练状态每轮各使用一次；batch 256、microbatch 16、AdamW `lr=1e-4`、`weight_decay=1e-4`、clip 1。共享主体和价值头可训练，策略头冻结；按验证 MSE 共同恢复最佳模型和 AdamW。
- 第二阶段从合成阶段最佳 checkpoint 和对应优化器继续。最终留出只推理一次，按整局 bootstrap 汇总 MSE、MAE、相关性和明显优势方向准确率，并比较恒零及训练集均值常数基线。留出来自旧训练对局的重新按局划分，不属于新采集的独立数据。

## 数据来源与生成

288局来源由原始bootstrap运行的32局，以及后续8个刷新批次各32局组成。它们都是同一随机初始化策略的完整自然胜负对局，双方直出采样、0 MCTS；每位玩家在每个真实决策点独立以50%概率保存一条价值样本。失败、截断和平局不生成训练记录。最终得到76,236条已采样FAIR决策状态；W/L终局只用于筛选完整胜负局，本实验的监督目标始终由公开塔血计算，不使用终局胜负标签。

合成阶段没有遍历全部76,236个状态来扩增。索引器按固定顺序扫描已采样状态，在每个数据分区收集最先遇到的8个简化FAIR模板：无部队、效果和事件，六座塔均存活；手牌、Tracker和其余FAIR输入仍保留模板的原值。当前实际清单中，训练8个模板来自原bootstrap的6局（0002、0003、0004、0006、0008、0011，其中0003和0006各贡献两个视角）；验证8个来自4局（0001、0009、0018、0023，其中0009贡献四个模板、0023贡献两个）。因此当前合成阶段只覆盖16个原始状态模板，而且这些模板都来自最初32局；其余刷新批次的状态尚未参与这一阶段。

每个模板扩增为`41个可行塔血差档 × 3^6=729组塔间分配权重 = 29,889条`。`0.25、0.6、1.0`是六座塔之间分配剩余血量的相对权重，不是把塔直接设为25%、60%或100%血量。对每档目标分数，程序按塔的存活和国王塔激活约束分配六塔HP，再同步改写输入中的HP比例和归一化绝对HP；其他FAIR字段不变。各组扩增样本共享其模板上下文，因此不能视作29,889个独立对局或独立场景。

真实上下文阶段使用全部训练分区的61,296条已采样FAIR状态。每条状态生成原塔血版本及三个确定性反事实版本，反事实分数取该状态可行范围的10%、50%、90%位置；只改六塔HP输入和由此计算的软标签，其余状态字段逐位保留。该阶段将实际覆盖此前刷新批次中的状态，而非只重复16个合成模板。留出状态在最后评估前不会生成变体或读入训练。

## 运行身份与恢复

固定初始化模型 SHA 为 `14fbd5fa43ba84be860f4333f3c63a935879b2ca0d6221978100c93cb6061415`，随机种子为 `20261103`。服务器 PyTorch 与原始初始化环境版本不同，因此从经模型/架构/零优化步校验的初始化 checkpoint 载入精确权重，再新建本实验 AdamW。每代 checkpoint 保存模型、优化器、Python/CPU/CUDA 随机流、数据分割、源码和父 checkpoint 身份；阶段结果只在完整轮次和最佳模型/优化器往返校验后提交。

训练节点使用单张 CUDA GPU；先以相同 16 状态验证 CPU/CUDA 前后向、策略头不变、输出数值和三步耗时。启用 PyTorch 确定性算子时，CUDA 运行必须提供 `CUBLAS_WORKSPACE_CONFIG=:4096:8`。本机 MPS 的首次启动在第 1 轮完成前按用户要求停止，仅有第 0 步基线 checkpoint；不把其部分梯度计入本实验。远端使用新 run ID，不继承本机 MPS 运行身份或训练状态。

启动与恢复均使用 `native_runner.training.sspi.tower_counterfactual` 的显式来源、数据目录、run ID 和初始化 checkpoint 参数。每个数据索引和 checkpoint 校验 SHA；恢复只接受匹配 run 身份及完整 epoch checkpoint。失败或截断局不生成标签，平局来源按原协议排除。实验不启动 AVD、引擎或新对局采集。

## 验证与结果

本机新增塔血定向测试14项通过；塔血反事实、共享主体及预热回归合计52项通过。仓库公开检查1,104 passed、42个既有skip，主工程回归470 passed。服务器实际CUDA前后向与更新探针通过；完整两阶段训练指标、最终留出和预设门槛结论以运行完成后的持久结果为准，工程测试通过不构成拟合成功证据。

训练运行ID为`sspi-tower-counterfactual-20261104-v3`，使用服务器 `.34` 的单张 Tesla V100，未使用本机 MPS。16个真实FAIR扩增样本的CPU/CUDA三步正确性探针均通过；CUDA与CPU初始logit最大差`1.16e-8`，热身后三步中位耗时分别为`0.392s`和`1.303s`。本机塔血专项与共享主体/预热回归共52项、公开检查1104项（42个既有skip）、主工程470项通过；文件扫描gitleaks无发现。
