# SSPI 输入与信息通路诊断、候选架构

日期：2026-11-05。状态：完成源码审阅与离线输入探针；下述新架构为待验证设计，未替换模型、训练、采集新局或操作原生引擎。

## 1. 诊断范围与结论

基于 main `078359e796d8077becd11fa557fee92b8117fee7` 的当前 SSPI 二分类模型，而非旧 RL1755 标量价值网络。当前模型共 **7,869,645** 个参数：共享编码与主干 **6,923,203**，策略头 **814,600**，价值头 **131,842**。

核心判断：输入文件约 100 KB 本身不是最有力的失败解释。优先修复的是关键数值的尺度、传递路径与语义组织；另有固定容量填充导致的计算和存储开销。现有事实支持这些问题值得优先验证，但尚未证明任何单项解释此前训练失败。

离线样本来自历史 SSPI 8 个完整对局的 **210 个搜索根**，每局首、中、末共 **24 个状态**用于随机初始化信号诊断。这不是全部 288 局训练数据的分布审计，也不是已训练 checkpoint 的诊断或耗时基准。统计代码在反序列化时校验 FAIR 摘要；探针没有优化器步骤。

机器可读汇总：[SSPI_INPUT_ARCHITECTURE_AUDIT_RESULTS_2026-11-05.json](SSPI_INPUT_ARCHITECTURE_AUDIT_RESULTS_2026-11-05.json)。公开文件只含聚合统计、源码与来源摘要，不包含原始 FAIR 张量、逐状态输出或权重。原始附件保留在私有工作区，公开摘要不宣称足以独立重放私有样本。

## 2. 约 100 KB 到底是什么

下表是还原为模型所用 FP32 浮点后的 frame 张量存储字节数，整数与布尔字段保留其实际 dtype；不含 Python 对象、压缩存档、激活、梯度或优化器内存。它不是 100,000 个独立浮点特征。

| 输入部分 | 平均字节数 | 说明 |
| --- | ---: | --- |
| 战斗组与子实体 | 61,520 | 48 组、160 子实体的固定容量以及字段/掩码 |
| 显式空间平面 | 32,256 | 14 × 32 × 18 × 4 |
| 旧候选输入 | 4,312 | 当前仍经过 candidate encoder |
| 事件输入 | 3,104 | 当前神经摘要置零，仍留在 frame 协议 |
| 己方卡牌 | 728 | 8 张稳定卡组身份及动态字段 |
| 对方卡牌 | 819 | 9 槽，包括不确定性相关表示 |
| 防御塔 | 798 | 6 塔的血量、运行状态、几何与掩码等 |
| 关系边 | 788.81 | 随场景变化 |
| 前一动作 | 148 | 当前神经摘要置零 |
| 对局标量 | 72 | 18 个浮点数，部分字段由 snapshot 路径置零 |
| 活跃效果 | 7.55 | 随场景变化 |
| **frame 合计** | **104,553.36** | 约 104.6 kB / 102.1 KiB |

此外还有手牌/补牌 128 维 FP32，即 512 字节，以及实际动作合法性合同。例如 4 卡 × 576 格 × 5 延迟的布尔表是 11,520 字节；这不等于上述 frame 的组成，也不意味着所有样本都有此形状。

这批样本平均只有 **6.88 / 48** 个有效组、**8.48 / 160** 个有效子实体（最多 20 个）；子实体槽约 **94.7%** 为填充。空间平面平均 **99.50%** 为零。掩码保证语义正确，不会自动跳过此前已执行的 Linear、MLP、QKV、FFN 运算。

72 个子实体数值字段中，49 列在本样本的有效实体上始终为零。这只能作为进一步审计的线索：固定速猪不涉及的机制、真实为零与尚未观测的字段应分别判断，不能根据 8 局统计直接永久删除。

## 3. 当前信息路径

```text
子实体 160 槽 × 72 数值字段 + 静态语义
  → 每个子实体 128 维
  → 每个因果组汇聚为 4 个 128 维槽
  → 48 个 256 维组 token

6 塔 token + 8 己方卡 token + 9 对方卡 token + 48 组 token + STATE
  → 4 层关系 Transformer，宽 256、8 头、FFN 1024
  → STATE 256 与各 contextual token

14 显式空间通道 + 32 学习式子实体 scatter + 3 坐标通道
  → 64 通道空间卷积与 3 个残差块
  → 空间特征图 + 128 维全局摘要

18 对局标量 → 128
128 手牌/补牌特征 → 128
旧候选编码 → 128

[STATE256, 空间128, (对局128 + 手牌128), 候选128]
  → 640 → 512 + 两个残差 MLP 块
  ├─ 策略：共享512 + 卡 token + 空间图 → mode/card/cell/delay
  └─ 价值：512 → 256 → WIN/LOSS 两类
```

关系 Transformer 类名含 Sparse，但当前只是关系边的来源稀疏；注意力实际构造完整 72 × 72 矩阵。不要将其称为只对真实关系边计算的稀疏注意力。

战斗组按 deployment、spawn_wave、volley、persistent_effect 等因果来源组织。子实体是单位、建筑、投射物等可见对象；不是把一个对象的碰撞体统一称为子实体。

源码定位：`training/sspi/model.py:179–278`、`training/az_joint/model.py:14–47`、`training/v4/components.py:322–413,437–467,585–717`、`training/v4/model.py:356–437`；路径前缀均为 `firstlight_CR/native_runner/`。

## 4. 按优先级排序的问题

### 4.1 塔几何支路与动态数值尺度明显不匹配：有直接测量

TowerEncoder 先计算 `MLP(塔数值) + Linear(位置及边界) + 类型/归属/机制/效果嵌入`，再做 LayerNorm。这里位置与边界是原始格子单位，未在这条 Linear 支路先除以棋盘宽高；关系注意力的相对坐标支路另外做了归一化，二者不能混同。

固定 `seed=20261103`，24 个真实状态的测量：

| 测量 | 均值 |
| --- | ---: |
| 几何投影 RMS | 8.998866 |
| 全部 21 维塔数值特征投影 RMS | 0.094808 |
| 二者幅度比 | 约 94.9 倍 |
| 己方公主塔当前血量全部减半导致的数值投影变化 RMS | 0.009172 |
| STATE 向量范数 / 扰动范数 | 15.9997 / 0.009583 |
| 共享向量范数 / 扰动范数 | 22.6266 / 0.010158 |
| P(WIN) 变化 | -6.16e-7 |

两处塔血字段（比例与绝对归一化血量）同步修改，塔位置、身份和其余字段保持。RMS 为整个塔张量的统计，并非单独 HP 特征的权重大小。

这提示随机起点的条件数不佳：固定几何背景很大，动态血量增量相对很小。LayerNorm 不会凭空恢复此前被缩小的相对差异，但它也不意味着血量信息被数学上彻底删除。随机输出应接近中性，单看随机输出变化小不是失败证据；应结合中间层尺度、输入 Jacobian 与训练后的对照判断。

当前价值最后一层还采用 `std=1e-3`，会缩小初始化时向前面隐藏层回传的梯度。AdamW 对整体梯度缩放有一定补偿，梯度绝对值小并不直接证明优化失败；不同输入方向的相对弱化仍值得检查。它不是唯一原因，也不建议仅靠放大输出层权重作修复结论。

### 4.2 塔血路径过于间接；空间分支没有独立塔血：源码与探针一致

塔血主要经过塔 token、全局关系编码、STATE/候选摘要和共享主干进入价值头。没有从原始六塔数值直达价值头的短路径。512 维本身不代表表达能力不足，问题在于网络必须先学会从多次混合中保留这一简单而重要的量。

纠正此前说明：14 个空间通道是己/敌各 7 个——地面单位计数、空中单位计数、建筑占据、投射物计数、单位 HP、shield、threat。构造器遍历 `observation.entities`；独立的 `observation.towers` 没有专门塔血通道。学习式 scatter 也仅接收 child_memory。24 个输入干预中空间摘要变化均严格为 0。

全局条件仍可使策略间接响应塔血，故这不是“策略完全看不到塔血”。但局部落点特征没有直接携带某座塔的剩余血量，不利于简单、稳定地定位危险。

旧 RL1755 的同类底层编码确实能学到塔血敏感性，且旧 value_context 有 scene/spatial/scalar 跳连；旧训练还含塔血势函数奖励。这个正对照排除了“该类编码理论上完全学不了”的解释，却不是单变量架构消融。

### 4.3 手牌与全局摘要相加，补牌数值尺度偏小：结构性风险

当前 `scalar_summary + hand_summary` 将两组各 128 维表示直接相加。两路可通过训练学习不同子空间，因此不能说必然丢掉全部可用信息；但它使来源分离依赖额外学习，也将只属于某张牌的就绪与补牌状态折叠进全局向量。

补牌剩余 ticks 除以 1200。本样本实际已知值为 2–28 ticks，编码约为 0.0017–0.0233，相比 one-hot 的 1 很小。建议按实际引擎 tick 时长映射到动作的 1 秒时域，并提供“200/400/600/800/1000ms 时是否已补到”的可推导特征。只有 FAIR 已知时刻才能给确定值；否则保留 known/uncertainty，补牌准入仍服从原生回执与既有执行语义。

### 4.4 因果组先汇聚，精确对象关系在全局推理前就压缩

每组四个 learned pooling 槽能表达组内结构，但一张卡生成多个单位后，它们可能位于不同位置、攻击不同目标。随后只有一个 group token 参与全局关系推理；空间 scatter 保留了一部分子实体信息，却不等价于保留完整实体身份与目标关系。

这属于有依据的表示风险，尚无量化消融。不能把四槽池化描述成简单均值，也不能断言所有战斗信息已经丢失。

### 4.5 模型视图继承了较多通用协议成本

旧候选编码约 79.35 万参数，本样本平均有效候选仅 0.548、半数为零；独立 SSPI 合法动作与条件策略另有路径。候选摘要仍可能提供成本、可行性与关系信息，替换前须映射全部语义，不能直接删模块。

事件与 previous_action 神经摘要已为零，协议字段仍有传输/转换/验证成本；可分离模型最小视图和审计记录。但 FairPublicTracker 的轮转、圣水估计与不确定性必须保留。去掉旧事件神经输入不等于抛弃合法推断所需的历史摘要。

## 5. 建议候选架构：关键数值短路径 + 实体关系 + 空间分支

保持 FAIR、无循环记忆、WIN/LOSS、WAIT/PLAY/ABILITY、五档延迟以及既定训练损失。预算保持约 8–10M；以下宽度是设计建议，准确参数量与性能需实现后统计，不以更多参数补偿不良编码。

### 输入层

- **固定角色塔表**：己方左/右公主塔与国王塔、敌方相同顺序；保留 HP 比例、同一单位归一化的 HP/maxHP、存在/存活/激活及必要 known 位。显式保留原数值，不仅保留经 LayerNorm 的嵌入。
- **数值尺度**：位置/边界除棋盘宽高，速度按合理单位归一化，冷却/补牌用秒与当前动作时域；所有缩放固定版本。真实大值、未知值、填充与零分开编码，不靠过度 clipping 隐藏差异。固定物理尺度归一化与对单个状态的血量向量做 LayerNorm 不同；后者可能丢失整体血量幅度，因此必须保留原数值旁路。
- **每卡动态信息**：将 ready、轮转/FIFO、补牌倒计时及 known 位、有效花费接到对应卡 token；稳定卡组身份与物理槽位分别维护。槽位重编号不应改变按 card_id 表示的动作分布，须测试。
- **对手信息**：只接 FairPublicTracker 的公开推断和不确定性，不接真实隐藏手牌、圣水、牌序或引擎私有状态。
- **真实实体表**：保留精确对象身份、类型、所属方、位置、HP、速度、攻击/目标关系及当前机制字段。按有效实体数打包并分桶 padding，保留现有安全容量及溢出报告，不因本样本最多20个就把容量砍到20。
- **静态语义**：按 card/archetype ID 查询必要机制；活跃效果挂接实体。保留静态缓存的既有正确性规则，训练参数变化后不复用过期缓存。

### 编码与主干

1. 真实实体、六塔、己/敌卡牌编码为 256 维 token。因果组身份改为关系/来源属性，避免强制“先每组压成一个 token，再跨组推理”。关系边只来自公开状态。
2. 复用 4 层、8 头、FFN1024 的关系模块，按真实 token 数分桶；加入少量策略/价值查询，分别汇聚上下文。直接实体 attention 在拥挤场景可能比现有组 attention 更贵，必须测典型与高密度状态，不能预称提速。
3. 18×32 动作网格保持。保留实体 scatter 与 64 通道空间分支，增加己/敌塔血及塔存在通道；通过全局数值投影条件化空间残差块。设备端重建空间平面属于可测工程选项，不是默认更快的结论。
4. 数值、卡牌就绪、关系与空间摘要采用独立拼接后投影到共享 512，不将不同来源摘要直接叠在相同坐标上。
5. 保留六塔 contextual token 的独立读取，不要求全部价值信息只从单个 STATE token 恢复。

```text
当前 FAIR 状态
  ├─ 六塔/时间/圣水等关键数值 ────── 数值 MLP + 原数值旁路 ───┐
  ├─ 每卡身份、就绪、补牌/公开轮转 ─ 卡 token ────────┐        │
  ├─ 真实实体、塔、效果及公开关系 ── 关系 Transformer ┤        │
  └─ 实体及塔的空间图 ──────────── 空间 ResNet ─────┤        │
                                                    ↓        │
                                             共享上下文512   │
                                               ├─ 策略支路   │
                                               │  +卡token/空间图
                                               │  → WAIT/PLAY/ABILITY
                                               └─ 价值支路 ←─┘
                                                  → WIN/LOSS
```

### 价值头与策略头

建议价值 logits 采用两路相加：

`z_value = MLP_context(concat(shared, tower_context, numeric_context)) + MLP_short(raw_public_numbers)`。

例如 context 路径从 768 维到 256 再到 2，short 路径用 64 隐藏维。short 分支归价值头所有，value-head-only 阶段也能训练；它学习公开数值与价值的关系，不硬编码塔血差为胜率，不将当前启发式训练目标本身塞回输入作“拟合成功”。

策略仍分解为 mode → card → cell → delay，保留独立合法性合同和空 ABILITY 掩码。策略/价值各有小型专属读出；只训练价值专属参数时策略保持，更新共享层时策略仍可能漂移，必须继续报告，不承诺两者完全解耦。

### 与已有架构经验的关系

AlphaStar 的公开架构采用 scalar/entity/spatial 分路、Transformer 与实体 scatter，并保留多种跳连；KataGo 将全局标量和全局池化结果注入空间卷积。这里借鉴的是输入类型与信息通路的组织方式，不照搬其循环记忆、训练时额外对手信息、训练算法或算力规模。

- KataGo 原始论文：§3.3 与 Appendix A，https://arxiv.org/html/1902.10565v5

## 6. 建议实施顺序与验证边界

先做一个小范围候选，而不是同时重写全部编码器：

1. 修复塔几何归一化，加价值数值短路径，把 scalar/hand 改成独立拼接，并将补牌时间按动作时域表达。
2. 用现有训练/开发样本检验：分支 RMS、HP 输入 Jacobian、同步双字段有限差分、小批过拟合、验证 MSE/MAE与常数基线。不重复消费冻结最终留出集作开发调参。
3. 再验证每卡输入绑定、塔空间通道与实体直接关系；每次记录对应归因，不开展无边界架构或参数量搜索。
4. 最后做动态打包、模型视图精简等效率优化，分别测端到端延迟、峰值内存和密集场景；空槽比例不等于实际提速比例。

验收必须包含：FAIR 可见性、塔血与视角一致性、slot/token置换、2/3 张手牌与延迟补牌、非法输出处置、动作随机流、原生状态/模型协议版本与 checkpoint 身份。新架构须新版本、新运行，不把旧 checkpoint 静默当新结构加载。

启发式拟合、终局价值预测、无搜索策略胜率是三个不同层级。拟合塔血公式只证明数值路径可学习；更好架构、实战提升及60%胜率均有待后续实测。
