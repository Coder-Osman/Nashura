# 进行中原生对局：独立进程重放恢复

## 机制与边界

`RecoveryJournal` 是实际比赛基础设施，不是策略或信念世界接口。原生快照仍然是进程内
handle；C++保存的ByteStream wrapper包含堆指针，restore还依赖manager generation、
state epoch、塔兵runtime和控制器sidecar。目前没有经过验收的持久snapshot import/export。

采用同配置、同seed和已落盘动作组在新引擎内重建。只在故障恢复时重演历史；正常
搜索继续使用原有进程内快照，不增加每根从开局重放的工作。恢复成本随已运行长度增长，
不声称O(1)跳转。

## 写入契约

- 独立私有审计目录，`training_admissible=false`。保存真实seed、reset配置和双边
  execution RNG，仅由恢复基础设施读取；策略回调只收到同tick冻结信息和玩家RNG。
- manifest绑定引擎、checkpoint、部署源码、controller、adapter和逻辑episode ID。
  新进程从精确开局启动，校验实际match配置、RNG及首帧证据。
- 同tick双边选择作为一个原子动作组。先持久写入完整动作意图、前后RNG与边界
  证据，随后提交controller；中途退出后在新引擎执行该组一次，不向旧引擎重发。
- 每个新决策边界和原生终局自动checkpoint；可显式记录尚有预约的中间tick。
  最后未落盘的推进重新计算，不把它计为新增有效决策或对局。
- 不可变序号文件、前驱SHA链、文件fsync、父目录fsync；单写者文件锁且绑定PID。
  半写临时文件不是完成记录，已发布记录损坏、序号缺口或身份差异均停止恢复。
- 校验FAIR帧及合法掩码SHA、时钟、预约生命周期、native digest、玩家执行RNG。
  预约证据以增量哈希链记录，避免每个根重新序列化整局历史。
- 已观察到的原生拒绝或截断写入持久quarantine标记；重启先检查隔离标记，再
  创建引擎。进程退出本身可恢复，但已判无效的尝试不会借恢复路径重新成为有效局。
- 恢复重放不调用模型、不重新采样，只重建已落盘行为；后续未提交决策使用恢复
  后的RNG继续正常采样。

API调用者须持有独立可信manifest SHA。验收探针另外固定最后checkpoint的
record SHA和记录数，恢复完成后核对链头；仅依赖目录内的自述哈希不等同于
防止恶意重写或完整尾部回滚。本实现面向本地单写者、可信审计存储的进程故障恢复。

## 本轮验收

单测覆盖冻结/预约中边界、同tick原子动作组、私有单边唤醒、抢占、原生终局、
RNG/帧/时钟一致、重复恢复、并发写锁、非法/拒绝/截断、日志损坏和身份错误。
独立Python子进程在动作意图fsync后、内存提交前执行`os._exit(73)`，父进程
恢复完整动作组且预约编号不重复。

原生验收入口：`run_recovery_probe.py`。在`.35`独立目录、端口29621运行源A
全合法分布CPU FP32采样；中段有预约时保存日志，基线继续至完整终局；退出原
Python worker和原生引擎，重新启动两者，重放至保存点并继续到终局。报告比较
所有后续边界的FAIR/掩码SHA、动作组、native digest，以及完整时钟、RNG和结果。
实际结论以`native-recovery-report.json`为准；失败attempt日志保留。

## 不在本轮结论内

- 不是Full128搜索器实现，也没有持久化搜索树或未完成访问。
- 不是正式采集器与SearchResult/训练行存储的最终集成；此前EpisodeStore负责完整
  局的原子发布，本接口只验证运行时恢复。后续接线须按稳定预约ID重建或去重行。
- 不是CUDA推理逐位确定性、整局FAIR非干扰、五机容量或策略强度证明。
- 不发布模型，不启动迁移采集或正式训练；整体G0/G1保持IN_PROGRESS。
