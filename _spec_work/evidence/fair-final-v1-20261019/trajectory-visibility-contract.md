# 整局 FAIR 可见性子项

此项只验收新版运行时和源 A 适配器的输入隔离，不放行正式采集或模型发布。

## 修复及复现

- 事件权限取交集：oracle-only 永远排除，private_to 只允许所属玩家，combat 可见性继续限制访问。
- 新版 tensorizer 每次观察校验对手私有字段和 native digest，不只在开局校验。
- 私有或单边可见部署事件不触发双方决策。
- 首次真实探针在中段复现共享256条事件队列的侧信道：对手私有事件虽在输出时过滤，
  仍会挤掉本方可见事件。失败记录保留在 visibility-visibility-1792415096673722000。
- 新版在事件入队时分流为双边独立有界窗口，历史摘要同样独立；原共享窗口保留作审计。
  两个新窗口各最多256条，不保存无限战斗历史。旧运行时保持原样。
- 完整快照包含双边窗口和摘要，恢复试验核验随后观察、动作、预约及原生结果。

## 整局验证

固定源 A、CPU FP32 和执行 RNG；开局、中段、后段、加时首次双边均可决策时检查。
每阶段分别对两个玩家执行四类扰动，共32项，所有试验均在独立快照中恢复：

1. 真实原生对手手牌/牌序交换：要求原生状态摘要变化，本方完整 FAIR 观察、帧/掩码、
   候选、条件概率、采样动作/logp 和 WDL 逐项一致。
2. 更改 Python reset seed/deck 元数据：观察到的策略输出不变。
3. 经生产入队入口注入对手 private 和 oracle 事件：本方观察及策略输出不变。
4. 对手 WAIT 与未到期 ACT 分支比较：最短执行延迟之前的下一 tick，
   本方观察/帧/唤醒状态和原生摘要一致。该中间帧仅用于诊断，不记录训练行。

全局只在真实决策边界采样，逐次校验合法动作与事件权限，要求原生 finalized 完整终局。
报告和原始日志、部署清单、远端 runner、清理记录均绑定 SHA。SSH 断线后可用
`run_visibility_validation.py --case visibility --collect-existing <run-id>` 回收已完成结果；
回收须核验当前源码与部署身份一致，且所属进程退出，不重新运行或伪造完成记录。

## 结论范围

- 这是四阶段、双座位的固定轨迹回归，不是穷尽所有可能游戏状态的证明。
- 元数据 seed 扰动不等同于修改原生 PRNG 内存；手牌交换不证明合法条件后验重建。
- 尚未覆盖真实 Full128 搜索、模拟对手端到端隔离及全部隐藏实体机制。
- `training_admissible=false`，只放行 `G0.FAIR_TRAJECTORY_SUBSET`，整体 G0/G1 保持进行中。
- 结果以 `trajectory-visibility-report.json` 及最新 `gate-status.json` 为准，
  原生时序、正常终局/平局、跨进程恢复必须使用最终相同源码重新验收。
