# 其余随机对象：静态清点与四阶段只读诊断

## 本轮范围

依据冻结规格 ACCEPTANCE_GATES.md 的 G0/G1 FAIR 非干扰要求，先清点对象及调用关系，
不将上一轮 manager PRNG 非干扰结果扩展为所有战斗随机源覆盖。
不改已验收运行时、原生库、策略模型、训练配置或旧证据。所有新增工具位于 tools 与证据区。

## 静态证据

固定 libg SHA：`110aa2b5cac391c498645e072b0d88729428c2c2845e7e2737ca8ee979059783`。
扫描全部可执行 PT_LOAD 中对八个已识别随机函数的直接 B/BL 引用，
同时逐指令核验21个定位锚点；保存调用地址、上下文及段哈希，支持从原二进制重建比对。

- xorshift生成177处，保存／恢复各8处；MT样式初始化18处、生成43处。
  这些是静态引用数量，不是当前对局实际执行次数。
- `manager+0xa8`存在时快照走world分支；`manager+0x50`的
  `+0x550/+0x554/+0x558`三个状态属于另一路对象，不应未经运行核验纳入本次战斗对象。
- `world+0x10`对象有独立结构序列化，但所查保存／恢复入口未调用已识别随机序列化函数；
  不据此将它标成PRNG，也不宣称间接调用已排除。
- `0xd35f9c`的MT样式对象以manager当前tick初始化，同一路径内清零并释放；
  这是临时对象线索，不是一个始终驻留、可按固定地址扰动的状态。
- 组件vtable `0x189f900`，随机字段 `+0xc0`；`0xf4f100`开始的初始化路径
  从关联实体取得world/manager，以`tick×12345`作为`0x121b2e4`的参数；
  `0xf4f7a0/0xf4f80c`调用随机生成。尚未确认其在固定速猪路径中的实例、
  存活范围及快照覆盖，因此不对该状态做内存写入或宣称非干扰通过。

## 原生诊断预注册

`.35`，独立端口29648，一个所属真实引擎，无信念引擎、无Full128搜索、无训练数据发布。
采用已有固定源A采样策略轨迹和独立执行随机流，阈值100/1200/3600/5400，
各取阈值后的双方ready边界。内部900秒、外部960秒上限。

- 继承已验证的PID/start_ticks、cwd、命令、库SHA、唯一映射和tagged指针守卫。
- 暂停自己的原生进程并核验所有线程静止、worker空闲、代次/epoch/tick一致后，
  只以O_RDONLY打开进程内存；记录manager状态及两条备用分支是否存在。
- 核验`world+8`反向指针确属该manager，不对未证明归属的地址读写。
- 每阶段核对只读前后原始观察和digest相同，并拒收三类过期请求。
- 每阶段快照后重复同一原生tick推进两次：动作、游戏tick、诊断状态与digest逐项一致；
  最后恢复根并释放句柄。恢复产生的新epoch不作为游戏语义差异。
- 只清理本次进程，记录所属PID已退出、端口释放，保留所有失败尝试。

## 判定边界

本项通过仅表示静态清单可重现、选定轨迹四阶段对象分支及快照续步一致。
不能替代：组件随机状态动态定位、间接随机调用覆盖、Full128隐藏随机扰动、
一般经验先验、局部独立重条件化或完整训练闭环。G0/G1整体仍未放行。
