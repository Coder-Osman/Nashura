# 冻结策略直出训练独立价值头

本实验采集 4,096 局完整直出自博弈，随机初始化独立胜/平/负 MLP，仅训练价值头。策略及编码器保持冻结。五机目录为 `/home/<user>/fair-value-direct-20261012`，中心、数据和学习器位于 `.35`。原 `.34` 流式学习器保持运行。

## 固定配置

- 初始 checkpoint SHA256：`ddfb5c3a7cf0be236093c926e9c3ddb23731c150bd018db5cc669d24250ac71f`。
- 固定速猪、FAIR 信息、原事件动作与延迟契约。双方合法自回归分布温度均为 1，无搜索或 Top-K。
- 冻结任务 ID 与种子 12610000–12614095；预先固定 3,072 / 512 / 512 局的训练、验证、测试划分，同局双方及所有时刻保持同一划分。
- 仅完整原生终局可进入数据集，失败和截断隔离；胜/平/负类别顺序为 0/1/2，按该行玩家视角标注。
- `ValueEpisode` 与搜索数据独立，不构造虚假访问数，不进入策略回放池。

## 调度和资源

旧教师评测暂停时保存了 34 局完成结果；各机剩余任务记录在旧目录的 `paused-for-value-training.json`，本地汇总为 `paused-teacher.json`。未完成局之后按原种子重跑。

每台从一个常驻 actor、一个独占引擎开始；首 32 局配额为 `.34/.35` 各 7 局、其余各 6 局。用户要求提高正式采集并发后，扩容阶梯调整为每机 8 → 16 → 24 actor；`.34` 始终只有一个，总目标 97 actor。首批中央原子发布、校验和去重全部成功后，按压缩体积估算全量空间，进入八路阶段。每档健康观察至少 600 秒，且各机均有新的完整成功局、阶段内未新增失败，才继续扩容。配置保存在独立 `capacity.json`，不改变数据、种子和策略身份。

`.35` 的 actor 轮转分配到 GPU0–6，GPU7 留给价值学习；其他采集机轮转 GPU0–7；`.34` 使用 GPU6。24 路是本轮采集的目标上限，是否达到最优吞吐需看实际完整对局统计。中心 `capacity_history` 记录每档有效局/小时。升级采用暂停调度进程数秒、重启中心、恢复当前对局，然后等各机正在打的局完成，再更换 supervisor 的流程；已完成数据和进行中的对局保持有效。

八路阶段发现中心多线程反序列化争用，改用八个独立 CPU 进程执行相同的数据校验与原子发布。不同对局并行，同局发布通过文件锁串行，相同上传中的重试共享校验任务，任务分配与 attempt 在入库后再次核对。协调器状态锁不覆盖耗时的数据解码，心跳和派单保持独立。

升级期间旧入库队列积压和连接中断产生 33 次临时上传失败，触发分片保护，记录全部保留。修复后经显式 `/resume-hosts` 核验恢复；恢复只接受资源健康且无协议错误、无 blocked 任务的分片，保存恢复原因与历史失败数，重新开始十分钟观察。重跑继续使用原种子和递增尝试编号，不把失败计数清零。

健康门槛：可用内存至少 32GiB、可用磁盘至少 5GiB、连续三次采样无换页增长。资源不足停止新派单；协议和数据错误阻止受影响机器继续领任务。临时网络/引擎错误最多尝试三次，失败证据持久保存。数据上传中心校验成功后，actor 才清理该次临时压缩副本。

中心 HTTP 使用随机 bearer token，仅保存在权限为 0600 的 `connection.json` 中。五机原始权重、部署代码和原生运行文件分别做哈希核验。状态输出不含 token。

## 训练和验收

冻结 FP32 特征按局缓存，包含源数据、策略和输入语义身份，每局随机重算三帧核验。新 MLP 隐藏层随机初始化，末层零初始化；AdamW 学习率及 weight decay 均为 1e-4，batch 256，梯度裁剪 1.0。均匀选局再选行，最多 20 轮，验证 CE 连续五轮未改善早停。每 100 步与每轮结束保存独立恢复 checkpoint。

4,096 局采集已完成，共 1,084,736 行、7,504,751,582 压缩字节。特征编码改为五机 34 路：`.34` 使用 GPU6–7 两路，其余四机各使用 GPU0–7 八路。每个进程加载同一冻结策略，先与中央参考缓存重算三帧交叉核验，再动态领取整局任务；已有缓存直接下载并重新核验，不重复编码。`.34` 临时文件写入 `/dev/shm`，避免其剩余约 4.9GiB 磁盘限制，其他机器使用实验目录的临时空间；始终保留至少 32GiB 可用内存和至少 5GiB 临时空间。

中央八个 CPU 校验进程逐行核对原始完整局的标签、玩家、tick、输入语义摘要以及 FP32 特征形状和有限值，校验完成后才发布缓存收据。任务状态独立保存在 `feature-state.json`；同任务重试须字节一致，错误保存证据并暂停派单。`feature-plan.json` 冻结数据清单、策略、参考缓存和工作进程身份。原串行编码的退出码 -15 归档为 `training/serial-pause-exit.json`，表示主动切换并行模式。

`training/features-distributed.active` 阻止提前启动串行编码；全部 4,096 局缓存通过后，中心自动接续原价值头训练和离线门槛检查。训练读取经过验证的缓存时跳过原始大帧的重复反序列化，仍核对缓存哈希及模型、源数据与冻结划分身份。部署入口为 `feature_fleet.py`，本机及 `.35` 的价值模块回归均为 25 项通过。

编码至 1,328 局时，`.41` 的 `value-01311` 在同局重算抽检中出现 1/512 维约 1.51e-5 差异，触发全队暂停。`.35` PyTorch 2.6 和 `.41` PyTorch 2.5 的独立复现确认 GPU 非确定性累加波动；启用确定性算法后，三个抽检帧各重复 20 次全部逐位一致，`.41` 整局 272 行编码及中央参考核验也通过。编码进程设置 `CUBLAS_WORKSPACE_CONFIG=:4096:8`、开启确定性算法并关闭 cuDNN benchmark，原有 1e-5 校验阈值保持不变。`recover_features.py` 保留旧状态和失败记录，重启并核验全部 34 路之后恢复派单；原失败任务保持同一数据、划分和工作进程身份，不重采对局。

用户要求增加并发后，`scale_features.py` 将 `.35/.37/.39/.41` 扩至每 GPU 两进程、每机 16 路，`.34` 保持两路，总共 66 路。扩容前暂停新派单，等现有编码全部完成，保存旧工作进程清单，再重启协调器接入新增进程；已运行的编码进程保留。数据划分、模型、参考缓存和确定性计算设置保持一致。启动后 66 路均通过参考核验，四台扩容机可用内存约 120–218GiB；扩容前 34 路最近两分钟入库 84 局，作为短窗口吞吐参考。

66 路编码、8 路校验实测 121.7 秒入库 107 局，约 3,165 局/小时，相比前述 2,520 局/小时提高约 26%；不同任务的短窗口比较不等于固定数据 A/B。测得中心八个校验进程各占满一个 CPU 核，因此 `scale_feature_validation.py` 进一步把中心校验扩至 16 路。协调器从 `feature-plan.json` 读取 `validation_workers`，默认 8、合法范围 1–32；完整语义和标签校验保持不变。

66 路编码、16 路校验在启动一分钟后测得 81.3 秒入库 113 局，折合约 5,006 局/小时，是扩容前短窗口的 1.99 倍。该时刻完成 1,927/4,096 局，66 路全部存活、无新增校验错误或换页，可用内存 `.34/.35/.37/.39/.41` 约 55/215/212/121/170GiB。短窗口速度仅用于选择当前容量，仍需以全量耗时确认最终收益。改动后本机和 `.35` 各通过 25 项价值模块测试。

全量 4,096 局缓存已完成，66 路编码进程正常退出。价值头完成 19 轮、60,515 步后按五轮未改善早停，最佳验证 CE 为第 14 轮 0.433477，旧迁移头为 0.949972；每轮约 32–34 秒。首次导出因部署清单遗漏新版 `model.py`，远端保存函数缺少 `replace` 参数而退出，训练与最佳 checkpoint 均已保存。修复将 `model` 纳入初始和增量部署清单，并增加覆盖导出后重载测试；本机与 `.35` 各通过 25 项测试，随后从早停断点接续测试集报告和导出，保留 `training/export-interface-failed.json` 及恢复证据。

恢复导出成功，候选 SHA256 为 `671f2213401ae95a2464d0ad2d44bd67e00ad85e6331ca33397f06c75764a50b`，最佳头来自第 14 轮、第 44,590 步。独立测试集 512 局，新头/旧头 CE 为 0.420323/0.942055，Brier 为 0.275807/0.556559；整局 bootstrap 的 CE 差值为 -0.521732，95% 区间 [-0.547454,-0.490171]，通过离线门槛。冻结策略哈希保持一致。报告副本为 `value-training-report.json`；随后 `.35` 自动启动四路搜索对照评测，实战强度仍待对局结果确认。

## 新价值头搜索对贪心直出：五机 128 局

按用户最新要求，暂停原两组混合评测，保留其日志和已有结果，优先进行新价值头搜索对初始策略贪心直出的 128 局。沿用独立种子 14610000–14610063，每个种子交换位置，总共 64 个分片。双方策略权重一致，搜索方使用新 WDL 头，每根完整 32 次模拟、1 个信念世界、关闭根噪声；直出方加载原初始 checkpoint。原始数据不加入训练池，不自动晋级。

用户进一步要求增加并发，五机 `.34/.35/.37/.39/.41` 扩至 4/36/32/24/32，共 128 路。每路仅打一个指定玩家位置，64 对种子的双方分别并行；每路独占一个真实比赛和一个信念引擎。原 64 路尚无完整结果，已核验停止并清理全部所属引擎，旧日志归档到 `value-direct-eval-64-paused-<timestamp>`。每机分批间隔三秒启动，仅在可用内存至少 36GiB 时启动新分片。`.34` 引擎临时目录放 `/dev/shm/value-direct-eval-128`；其它机器用实验输出目录。GPU 按分片轮转分配，`.34` 使用 GPU6–7，保留原流式学习器。

五机校验候选、初始 checkpoint、评测代码和引擎运行文件哈希。分片输出包含身份、逐根进度、完整终局及退出状态；汇总严格校验分片归属、配对种子、玩家、模型、代码、配置和终局标签，按完整种子对 bootstrap 计算 95% 区间。分片入口测试验证只启两个引擎、两次换边、结果身份、恢复去重和种子边界；本机与 `.35` 共 26 项测试通过。

## 查看与恢复

```sh

```

- 中心 `state.json`：任务状态、尝试编号、阶段和资源记录。
- 中心 `status.json`：有效局、训练行、吞吐、失败数。
- `episodes/<id>/completed.json`：经过校验的完整局收据，最后原子发布。
- `training/latest.pt`、`best.pt`：独立价值训练恢复点；`candidate.pt` 为现有搜索加载器兼容产物，策略与初始权重一致、优化器与搜索回放均为空。
- `training/report.json`、`done.json`：离线报告与是否通过门槛。
- `value-evaluation/summary.json`：配对实战报告，不表示模型已晋级。

中心可从任务状态和已发布收据恢复，学习器从缓存及训练游标恢复。任何被阻止的任务保留原种子，修复后再显式恢复，不通过替换种子掩盖失败。未完成数据不会作为平局或有效训练数据使用。
