# 已知随机入口的低开销插件测量

本版本只建立独立测量环境，不替换现有冻结运行时，不给训练数据开准入，
不关闭G0/G1、随机全覆盖或其他模型门。

## 构建身份与隔离

QEMU版本固定10.0.13，源码来自官方HTTPS发布，实测SHA256
`4a59b74dac7ead8b162a7c4595dcbbeebe989b90c89cfe6bb4dec5447342f6fa`。
这是传输来源与内容身份固定，不是独立签名验真。源码经Python data_filter
解包，跳过linux-user目标不需要的roms固件子树，保留其余路径/链接校验。

开发依赖通过现有APT元数据固定版本与SHA256，下载后逐包复核，仅解包至
独立目录。只在该进程设置依赖搜索路径；不使用全局安装，不改变原Python
虚拟环境，不升级系统运行库。PC文件和开发链接重定位逐项记录前后摘要。
独立Python wheel允许官方configure创建自己的构建环境，不改QEMU源码。
仅构建aarch64-linux-user，显式启用plugins，ninja最多四线程；每阶段有时间、
32GiB可用内存、5GiB磁盘与512MiB单文件硬上限，失败保留日志。

## 插件执行与输出

依据QEMU v10.0.13 include/qemu/qemu-plugin.h API版本4，在vCPU初始化回调
取得PC/X0/X1/X30句柄，以QEMU_PLUGIN_CB_R_REGS注册目标指令执行回调。
翻译回调只按事前校准的128个page-aligned base及八个固定入口地址注册，
不记录全部TB，不开exec/cpu/nochain，不写guest内存或寄存器。

以上是保留的v1/v2窗口模式。v3不假定跨进程映射一致：翻译时只为八个固定
入口的页内偏移注册候选回调；就绪前不记录寄存器。worker以只读审计得到本次
实际libg base，原子发布arm-base.txt。候选执行回调读取该文件一次，写ARM记录，
之后只在该base的八个精确入口取寄存器及写日志，其余立即返回。原始格式固定
v3，解析器要求ARM与本次before/opening/final地址一致；关闭前全程base不变。
reset两种正向对照仍必需。启动前的调用不在v3观察范围内，不把启动零计数
解释为未调用。参数既不增加游戏seed，也不改游戏的随机字节来源。

实际libg base在reset之前由只读进程审计核对窗内；解析时仅保留该进程真实
base的八个入口，其余候选base命中只作格式审计。v2以qemu_plugin_insn_vaddr
取得的指令地址识别执行回调，另存PC原始读数。官方API4寄存器接口调用
gdb_read_register读取CPU状态；块内指令的PC读数可能仍为块起点。最小AArch64
程序已复现旧等值校验误判，同时核验块内指令之前写入的X0读数；v1失败保留。
四个寄存器均须恰好八字节；线程间加锁，逐行flush，全局递增序号，最多一百万条。
输出使用独占创建，错误立即退出，正常退出写END及总数；256MiB硬上限不变。
默认解析仍要求END；序号错乱、格式损坏始终拒收。

resident监督器使用SIGTERM退出时，实测不保证调用插件atexit。独立v2支持显式
监督封存，仅在完整原生终局验证、probe成功退出、所属引擎停止并释放端口后
生成trace-seal.json。封存绑定日志SHA/长度、final_offset、report/cleanup SHA及
child_pid/start_ticks，并现场复核该所属进程已停止。独立验收重算所有身份、
终局、序号、行边界及正向对照；不补写END，不将封存称为正常atexit，不对旧
失败attempt补封存。观察范围止于final_offset，不包含后续关闭过程。
vCPU退出回调释放其寄存器缓存，允许后续线程合法复用同一槽位；重复活跃
初始化或未知槽位退出仍拒收，不将线程索引当作永不复用的身份。

按reset前、reset后、完整终局后的文件位置分阶段，不允许边界拆开寄存器行。
reset必须实际观测mt_initialize和xorshift_seed两个正向对照；空日志不作
未调用或不可达证据。对象归类与调用点只作本次观察汇总，原始寄存器和指针
保留在私有归档，不公开。

## 新旧运行时对照与独立验收

依次用三个独立原生进程运行同seed、同合法mask脚本的完整对局：原QEMU8.2.2、
新QEMU10.0.13不启用插件、新QEMU10.0.13启用插件。原游戏库、探针、冻结Python
运行时字节保持原身份；源脚本继续冻结同tick双方信息、合法预约和完整终局。

逐项比较全部决策的FAIR语义摘要、mask和动作、执行回执、完整结算时钟及终局，
同时比较每300tick及终局的原生JSON观察摘要。记录每进程的native payload及
全局MT摘要；不要求含进程内地址的原生快照字节跨进程相等，不声称此对照
证明所有游戏轨迹或平台等价。

新QEMU默认映射受跨进程地址随机化影响，固定窗口失配必须拒收。可选独立
测量配置对新QEMU两组同时传入-R 0x10000000000，预留1TiB guest虚拟地址空间，
不代表分配1TiB物理内存。原QEMU参考组保持原启动参数；该配置变化属于待验
的测量运行时，仍须通过上述全部完整轨迹比较。原非预留尝试及失败原样保留。
实测预留后仍有guest库地址随机化，第五次窗口模式失败也原样保留。v3使用
默认新QEMU映射，并绑定同一进程实际地址；不使用QEMU -seed强制guest随机源。

独立验收绑定外部固定launch/download摘要、原始归档字节、父快照内容验收、
构建源码与产物身份、探针及冻结运行时，重算插件记录和两个正向对照，核对
所属进程退出、端口释放和三个不同原生进程身份。任一组不完整、拒绝、截断、
行为不一致或缺正向对照都保留失败；不跳过对照、不把fixture当原生证据。

本版本结论范围仅为一次完整轨迹上八个已知函数入口的实际执行观察，不涵盖
其他随机算法、所有seed、所有合法动作或隐藏机制，所有总门标志仍为false。
