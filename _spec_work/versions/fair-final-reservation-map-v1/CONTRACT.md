# 预约到原生命令对象的独立限定验证

复用dispatch-command-v1的显式v4插件及17个原生指令点，不修改固定运行时、
游戏库或正在运行的Full128/terminal部署。三独立进程完整对局继续比较决策、
结算、终局及周期观察；插件版额外按每次同步入队的日志字节范围定位唯一构造
对象，再按同tick执行范围关联真实ct86入口。双方同时到期的预约分别入队，
不按执行顺序猜测归属；跨tick指针复用允许，同tick对象重复拒收。

独立验收从决策顺序重建预约身份、动作与到期时间，核对最终结算证据、完整
入队回执、日志边界和全部构造/执行记录覆盖。父验收继续重算原始插件日志、
虚分派目标、返回值及清理，不将记录中的映射声明作为证明。

这项实验只覆盖实际成功执行轨迹；一般合法拒绝、mask充分性、随机全覆盖和
完整Full128搜索局保持独立待验。原始地址、完整回执与寄存器日志私有保留。

映射证据来自同步入队区间内的唯一构造与后续真实执行对象，不读取命令对象
内部的卡牌或坐标字段。HandAction坐标随归档保留；本验收未独立重算格点到
世界坐标的转换，也未验证对象内部字段与该坐标逐字节相等。回执的owner、
handIndex和cardId属于Python接口回执核对，不冒作原生命令字段的内存证明。
