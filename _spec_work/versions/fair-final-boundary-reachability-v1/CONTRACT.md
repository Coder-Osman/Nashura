# 单方决策边界的条件可达性分析

本工具运行冻结 history-v2 的真实 FinalDecisionRuntime 与 DecisionClock，
环境只提供合成的公开执行/己方私有拒绝结果。不是原生引擎测试，不证明输入合法，
不修改运行中的部署，不将合成拒绝当作合法原生可达性证据。

## 有限覆盖范围

从双方同步就绪、无旧预约的活局根出发，各方可以选择 WAIT=60tick，或
ACT delay_slot=1..30，即2..60tick。枚举31×31种时间类别；对最早到期的
全部ACT枚举执行/拒绝组合。后到期动作在该边界尚未执行，不预设其结果。
卡牌与位置在此只按给定执行结果做时间等价归类；这不是完整合法动作空间穷举。

使用独立的最早到期公式核对真实运行时：令 d 为最早期限，D 为到期玩家集合。
若 D 中有公开执行的ACT，就绪集合为双方；否则就绪集合为 D。
只结算 D 内预约，公开执行另抢占未到期预约，最后冻结观察。
逐tick验证 d 之前没有新决策，冻结内容已包含当tick全部ACT结算。

## 有条件的归纳结论

假设：初始双方同步；WAIT固定60tick；ACT不超过60tick；每次到期ACT均成功并
公开执行；没有额外私有唤醒；当前局未终局。则每个后继决策根仍双方同步且无pending：

1. 最早到期集合含ACT时，其成功公开执行唤醒双方，并抢占另一方未到期预约。
2. 最早到期集合只有WAIT时，期限为60；另一方的期限至多60，所以必同时到期。
3. 两类结果都回到相同前提，因此可对任意有限个决策边界归纳。

这解释了合法成功轨迹为何持续观察不到单方就绪根，但不证明拒绝在固定速猪下
不可达。工具另枚举“较早ACT私有拒绝、另一方未到期”的双方对称反例：单方就绪
且另一方pending，是运行时允许的路径；其合法原生可达性仍需独立证据。
从已经错开的根开始，WAIT也可能单独到期，所以不得把该条件结论扩大到一般根。

结果绑定分析器、契约及native/timing/policy/visibility源码SHA；逐行矩阵用SHA256
承诺，可本机确定性重算。协议变化、边界提前开放、结算/冻结顺序或抢占不符均失败。
G0/G1、一般原生pending/fallback与全部随机机制覆盖保持开放。
