# 完整条件蒸馏批处理工程验证

## 目的及隔离

冻结部署每个合法位置单独重算教师FiLM空间键和双方延迟头，358行验证约2600秒。
本独立版本仅改变条件头的计算组织；既有主工程、history-v2和运行中任务原字节保留。
没有修改损失权重、采样、全合法前缀支持集、迁移日程或任何验收门槛。

教师每张卡复用一次空间条件化，双方延迟头每次处理至多64个合法位置。
条件KL仍按教师的模式、卡牌、位置质量加权，覆盖所有合法延迟；不采样、
不截断、不过滤低概率位置。WAIT-only不访问ACT头。贪心完整动作与WDL项保持。
策略温度仍为教师单位温度、学生训练原始概率。非法延迟0依然排除。

## 预定数值要求

FP32批矩阵与逐行矩阵浮点求和顺序不同，不要求新旧实现逐位相同。
比较完整条件log概率、完整联合损失、共享输入及所有可训练参数梯度、
裁剪后的AdamW参数和两个moments；比较容差分别为
log概率/损失atol=2e-6、rtol=2e-5，梯度atol=2e-5、rtol=2e-4，
AdamW参数atol=3e-6、rtol=2e-5，moments使用梯度容差。
冻结教师参数/缓冲区、冻结阶段encoder、全局RNG必须逐位不变。
新实现自身相同状态的更新与恢复仍要求逐位一致，不放宽既有恢复比较。

## 部署身份

build_payload.py只接收具有完整launch/payload/deployment SHA身份的父载荷。
只新增批处理模块，更新迁移入口和series实现身份；旧checkpoint不得跨实现恢复。
新实验从独立初始化开始，不导入旧优化器或旧选择进度。
原生CUDA对照尚待实际运行；本地fixture、条件头吞吐和原生完整训练分别报告。
该优化不关闭G0/G1，不代表G2拟合或实战强度通过。
