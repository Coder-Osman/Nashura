# 已知随机入口执行追踪：工程完成，原生测量阻断

2026-10-23。本版本新增独立校准/追踪入口、身份固定与有界收取、原始QEMU日志
独立验收。只登记工程成果，不登记随机消费者或G0/G1通过。

八个已知入口来自现有固定库清单；复用已验收global-rng-snapshot引擎，库与探针
字节不改。先校准guest base，再为第二进程登记128个候选base范围，reset前
核验实际base在窗内。日志使用exec/cpu/nochain，按精确入口PC保留寄存器块，
要求reset阶段xorshift_seed与mt_initialize正向对照；空日志不算未调用证据。

独立验收重算原始日志，绑定父快照证明、冻结源码、QEMU/service/探针与上传
身份，核对双进程、完整原生终局、双方合法mask、同tick预约和完整结算时钟。
依据官方QEMU v8.2.2 cpu-exec.c中“didn't start executing this TB”的分支，
另拒收Stopped execution记录、执行头与CPU PC不符、交错或残缺记录；不能仅凭
一条exec打印就认定函数已执行。私有原始寄存器、指针、动作及终局不公开。

## 实际尝试

1. native-execution-1792742528392975000：56.949秒，规则manifest未绑定CR_PROBE，
   calibration reset拒收；22份归档，所属引擎清理与端口释放完成。新attempt补齐
   独立环境变量，不绕过attestation。
2. native-execution-1792742735807630000：214.854秒，校准成功；1024个精确单地址
   过滤项下，追踪引擎未在原监督器140秒内就绪；28份归档，追踪日志0字节。
3. native-execution-1792743181710335000：214.408秒，将过滤项合并为128个小范围
   后仍触发140秒启动时限；28份归档，追踪日志0字节。
4. native-execution-1792743535284451000：300.412秒，独立wrapper将唯一启动等待
   从140延至600秒，原service磁盘字节不变，变换SHA单独登记。校准成功；追踪
   子进程在启动232.595秒后以-14退出，即SIGALRM，早于600秒监督器时限；
   28份归档，日志仍0字节。尚未独立绑定发出alarm的源码位置，不据此推断游戏机制。

后两类失败监督记录为exited，trace cleanup的clean=false按原值保留；已核验
所属子进程退出、端口释放，不能把“资源已释放”改写为“成功清理验收通过”。
精确launch/download摘要见failure-summary.json；当前第四次失败归档还经实际
独立验收器拒收。前三次原字节归档仍保留，未用新实现重写旧尝试。
