# 固定速猪已知随机入口的执行追踪

本版本补G0/G1随机机制清单中的“静态引用不等于运行时执行”缺口。独立新建
校准与追踪两个原生引擎，复用已验收global-rng-snapshot引擎和history-v2冻结
运行时；不改变既有Full128、terminal选优、游戏代码或模型。

QEMU固定为现场8.2.2及实际可执行文件SHA。依据官方v8.2.2源码
accel/tcg/cpu-exec.c的log_cpu_exec与cpu_tb_exec，以及现场-d help：exec日志在
执行TB前记录；cpu记录入口寄存器；nochain关闭TB串联，避免只记录链首。
不是把in_asm翻译日志当作执行证据，不开启单指令TB。

先在校准进程中只读取得guest libg base。第二新进程为校准base前64页至后63页，
128个可能base各建立一段覆盖八入口的连续小范围-dfilter，日志文件独立且有256MiB上限。
范围内的其它TB也可写日志，验收只保留精确入口PC；合并范围减少逐TB的过滤比较。
启动后在比赛reset前只读核验真实base位于登记窗；越界失败，不以空日志证明未调用。
最终按该进程精确base过滤多余命中，只接受完整PC/X00–X30/PSTATE寄存器块。
函数入口均为直接/间接转移目标，入口TB必须从该地址开始；本实验不声称捕获
跳入函数内部的绕行路径或其它算法。必须在reset阶段命中xorshift_seed和
mt_initialize两个正向对照，否则拒收整份追踪。

八入口为现有静态清单中的MT初始化/清理/取样、xorshift初始化/播种/取样/保存/
恢复。记录X00对象指针、X01参数及X30返回地址，按全局MT、当前manager随机字段
和其它对象分类；原始指针和寄存器仅在私有审计区，公开只给聚合结果和SHA。
按日志偏移区分启动、reset/warmup和FIRST_PLAYABLE_TICK以后实际战斗；后台线程
仍可能调用，单条记录不自动等同战斗因果。调用位置按LR-4记录，尾调用会保留
上游LR，因此不是立即调用点的完整调用图；重放/快照调用也需按阶段分别解释。

采样采用已有公开合法mask驱动的确定性速猪脚本，双方同tick先冻结视图再统一
提交，沿用100–3000ms预约及取消语义；只接受原生完整finalized终局，拒绝或
截断失败。内部900秒、外部960秒；检查32GiB内存/5GiB磁盘，仅清理所属引擎。
nochain启动开销较大；独立wrapper仅将已绑定service源码中唯一的140秒启动
等待替换为600秒，原service磁盘字节保持不变，变换后源码SHA单独登记；外部
启动等待660秒。此变换不修改比赛规则、推进、模型或其它正在运行的服务。
这不是模型强度实验，不生成训练数据，不宣称所有seed全覆盖或随机状态总门通过。
原始日志/决策/终局、完整部署身份和进程清理须独立验收后才发布有限实测结论。
