# RL 训练性能与租机建议（2026-09-19）

数据来自运行中训练的只读日志与系统采样；未变更训练配置。完整原始资料保存在 `artifacts/mixed-history-v1/performance-audit.json`。

后续更新：历史对手准备优化已从第 730 轮上线，准备阶段从紧邻部署前平均 51.85 秒降至 5.26 秒。第 731 轮完整周期为 133.56 秒，部署前四轮平均 182.19 秒。下面保留首次性能审计的基线与租机建议；实现、验收及样本范围见 [历史准备优化](history-preparation-v2.md)。

## 每轮时间

取混合训练稳定轮次 706–711，排除 705 轮进程首次启动；每轮 108 局：

| 阶段 | 平均秒数 | 占比 |
|---|---:|---:|
| 历史模型准备与分发核验 | 45.02 | 25.2% |
| 对局采集、传回与轮次校验 | 82.48 | 46.2% |
| 学习、导出与独立权重核验 | 40.38 | 22.6% |
| 权重归档 | 3.44 | 1.9% |
| 轮间维护 | 7.27 | 4.1% |
| 合计 | 178.59 | 100% |

约 20.2 轮/小时、2,177 局/小时。此区间未包含每 20 轮的大批轨迹归档，因此长时间平均可能稍慢。混合前 695–703 轮常见约 136–145 秒；700 轮有较长归档维护，704→705 包含人工部署间隔，两者不用于稳定速度比较。

## 主要限制

1. 历史准备代码按模型、主机顺序调用 SSH、Python 和 rsync。即便文件已缓存，每轮仍多次建连、导入 Torch 并核验完整历史 checkpoint。近期池两个模型时约 43 秒，第三个进入后约 53–55 秒。批量请求、常驻校验和仅传缺失文件可以保持 SHA 核验，同时减少固定开销。
2. 648 场稳定对局的平均循环耗时为 45.72 秒：环境推进与交互约 56.9%，推理调用约 31.8%，观察物化约 6.4%，特征构建约 4.4%。环境推进包含模拟器、数据传输、解析和回执处理，不等同于原生引擎纯计算。
3. 当前模型平均推理往返约 132 ms，其中排队约 55 ms，服务端合批执行约 58 ms；历史模型约 171 ms，其中排队约 94 ms，合批执行约 63 ms。平均批量分别为 5.4 和 1.36。执行计时包含输入组装及设备搬运，并非纯 CUDA kernel 时间。
4. 每轮等待最慢对局结束：平均单局约 46 秒，而采集屏障约 82 秒。已经同时运行 108 局，增加到更多端口不会直接增加本轮并发。应先降低单局延迟、推理排队和固定开销。
5. 采集结果跨机传回一般每台 0.6–0.7 秒；712 轮的 108 个压缩 shard 合计约 15.3 MB。每局约 57 MiB 的原始引擎响应主要在采集主机内部流动。当前集群网络带宽不是主要耗时项。

如果历史准备从 45 秒降到 5–10 秒，其余阶段不变，整轮理论约 139–144 秒，吞吐约提高 24%–29%。这是阶段预算估算，尚未实施或实测。

## 租机规格

当前五台机器均为双路 Xeon Gold 6130，每台 32 个物理核、64 线程，约 256 GiB 内存。

额外对 .34 连续采样 190 秒、每 2 秒一次，得到 95 个样本：采集阶段推理 GPU 平均利用率 10.3%、峰值 17%；更新阶段学习 GPU 平均 25.1%、峰值 89%。显存分别约 809 MiB、4,795 MiB。采集阶段整机 CPU 平均利用率约 25.3%，准备阶段约 5.7%。这是一个周期附近的阶段抽样，更新阶段还包含数据准备与校验，不能把阶段平均等同于纯反向传播效率；但足以说明当前没有显存不足或持续 GPU 满载的证据。原始采样保存在 `artifacts/mixed-history-v1/performance-followup.jsonl`。

建议先短租一个可运行真实引擎的现代 CPU 节点测完整轮次。可作为一个 18–24 端口采集节点或学习器的起始配置：

| 项目 | 建议 |
|---|---|
| 系统 | Linux x86_64 独占机/裸金属，或明确支持嵌套虚拟化的虚机 |
| CPU | 现代高频 32 个物理核起，核对独占资源；EPYC 9374F、Threadripper PRO 7975WX 等可作为候选 |
| 内存 | 128 GiB 起，256 GiB 更宽裕 |
| GPU | 1×RTX 4090 24 GiB；机房卡可比较 L40S 的实际报价 |
| 磁盘 | 至少 1–2 TB 本地 NVMe，长期轨迹另配归档容量 |
| 虚拟化 | 实际可读写 /dev/kvm，Android Emulator 加速检查及现有镜像冒烟测试通过 |
| 网络 | 多节点放同一内网；10 GbE 可作为实用规格 |

当前代码学习器和推理默认分别使用 cuda:0、cuda:1，但采集和学习分阶段运行，可以配置共用一张有足够显存的 GPU。当前 PPO 不会自动利用租来的多张 GPU。

这份 32 核配置不是完整五机集群的等价替代。若集中运行全部 108 路，可把现代 64–96 物理核、512 GiB 内存、1–2 张 GPU 作为试跑候选，或采用多个上述节点；具体并发须逐档实测。节点数量变化也需要调整当前固定五机的配额代码。

租机验收应比较固定 108 局、相同模型与种子的整轮秒数及每千局成本；分别测试 12、24、36 路并发。CPU 核数、显卡型号和显存大小都不能单独代表这套系统的实际吞吐。
