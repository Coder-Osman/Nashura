# 历史对手准备优化（2026-09-19）

`history-preparation.v2` 优化混合 RL 每轮进入采集前的固定开销。历史池选择、对战计划、训练样本过滤和 PPO 参数沿用 `mixed-history.v1`。

## 实现

- .37 一次请求检查整个池：每轮重新计算完整 checkpoint 的 SHA；复用已核验的导出描述，缓存命中时不导入 PyTorch。缺少索引时才导出，契约及推理文件校验成功后发布索引。
- .34 先核对本地推理文件；其他四台机器并行执行批量核对。所有已有推理文件仍逐轮完整计算 SHA，不用 mtime 代替内容核验。
- 每台机器只通过一次 rsync 传输缺失文件，传输后再次核对 SHA。全缓存命中时为 5 次 SSH、0 次 rsync。
- 全部主机准备成功后才开始采集。损坏、缺失源 checkpoint、契约不兼容、空间不足和断线均抛出错误，不替换对手或更换计划。
- `mixed-plan-frozen.history_preparation` 记录版本、总耗时、归档耗时、导出数及各主机传输数。

## 验证

本地 24 项相关测试通过；远端独立 learner 快照中 32 项测试通过，包括历史准备、对手分配、混合轮次及执行动作学习契约。另在任务审计目录用真实 SSH/rsync 验证两文件批量拉取、推送与 SHA 核对。

用 600、645、650、675、700 的真实权重做三次缓存准备测试，耗时为 4.901、4.901、4.884 秒，平均 4.895 秒；每次均重新核对 .37 完整 checkpoint 和五台主机的推理文件，导出及传输均为零。旧流程同样五份历史权重约 53–55 秒。

部署使用独立 `collector-history-preparation-v2-code` 和 `learner-history-preparation-v2-code` 快照。collector 仅新增准备模块；learner 更新准备适配器并新增模块和测试。切换前后均核对文件 manifest，保留原快照。

本地审计目录：`artifacts/history-preparation-v2/`；远端运行目录下对应 `history-preparation-v2-audit/`。

对比紧邻部署前的 725–728 轮平均值和部署后第 731 轮。排除 729→730 的人工切换间隔，以及第 730 轮重启采集进程的首次启动开销。周期统计到下一轮开始，包含正常轮间维护。

|---|---:|---:|
| 准备（含当前模型身份检查） | 51.85 | 5.26 |
| 采集、传回与核验 | 78.65 | 76.14 |
| 学习、导出与权重验证 | 40.97 | 41.43 |

准备阶段减少 46.59 秒，约 89.8%；这个完整周期快 26.7%，折算吞吐提升 36.4%。优化后的整轮比较目前只有一个无需重启的完整样本，长期速度还会随对局长度及周期性归档波动。历史准备本身已连续在 730、731、732 轮测得 5.012、4.923、4.925 秒，每轮均为零重复导出、零重复传输。

731 轮同样完成 108 局、180 条玩家轨迹，学习 6,305 条决策，排除 3,022 条取消决策，完成更新和 .37 归档。检查时训练正在第 732 轮。原始逐轮时间见 `artifacts/history-preparation-v2/timings.json`。
