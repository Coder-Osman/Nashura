## 规则

- 第一版只约束闪电（`28000007`）。
- 从已校验的卡牌资源读取实际半径：3.5 格；默认增加 0.5 格余量，检查半径为 4.0 格。
- 原生落点中心到目标中心的距离小于或等于检查半径时，保留该落点；最终仍与原生合法落点取交集。
- 目标来自当前玩家可观察的数据，要求敌方、存活、位置有限。包括空中/地面部队、建筑和塔；保留只有塔时的收尾机会。尚未激活但存活的国王塔也计入。
- 排除友军、中立对象、死亡或血量未知对象、弹体、效果对象，以及明确非公开或不可承受范围伤害的目标。
- 不把“普通单体攻击不可选中”等同于范围伤害免疫；受法术卡身份影响的召唤部队按存活实体处理。
- 使用 native 世界坐标计算，再应用既有玩家视角变换，避免 owner 1 的坐标颠倒。
- 闪电没有任何保留落点时，连带屏蔽选牌；所有牌均不可选时保留 WAIT。
- 决策时和下发动作前都检查同一规则。延迟施法期间目标离开检查范围时取消计划，计入 `cancelled_lightning_target`，推进一步后重新决策；原始采样动作、概率、奖励及经过时间保留在训练轨迹中。

这是“附近存在目标”的硬约束。由于增加了余量、动作有提交延迟，而且目标会移动或死亡，它不保证最终命中，也不奖励单纯使用闪电。

## 启用

新采集任务在 `tools/event_rl_rollout.py` 原有命令后添加：

```sh
--lightning-target-constraint --lightning-target-margin-tiles 0.5
```

`tools/demo_event_selfplay.py` 支持相同参数；与 `--no-mask` 同时传入会报错。评估通过 rollout 入口进行时也要传入相同参数，两侧均使用该规则。`--lightning-target-margin-tiles 0` 表示只用资源中的 3.5 格半径。

当前运行中的 fleet 调度器及配置未切换到新规则。后续使用新的运行目录和代码 manifest 部署时，应把这两个参数加入采集/评估命令；勿覆盖当前运行目录的代码。

## 数据与 PPO

- 规则版本和半径写入 shard contract 的 `action_constraints`；录像轨迹的 `stats.json` 记录同一信息。
- `EventLaneRecorderV1` 绑定采集规则，写入 shard 时拒绝相互矛盾的声明。
- 实际采样的 gate/card/cell/delay 掩码继续逐行存储；PPO 用保存的掩码复算概率。
- preflight 拒绝同一批更新混入不同规则、不同余量或旧的无约束 shard。
- 新 checkpoint 的 `rl_action_constraints` 记录该次更新所用的规则；这是来源记录，加载权重不会自动启用约束，采集与评估必须显式传参。
- 旧 shard 仍可单独读取、训练；它们不会被新规则重新解释。

## 本地验证

相关测试共 110 项通过（53.57 秒）；两个命令行入口的 `--help` 验证通过。

覆盖半径边界与余量、无目标屏蔽、其他卡保持原掩码、敌我及生命状态过滤、塔收尾、原生合法性取交集、圣水延迟、双方坐标对称、采集与录像入口一致性、执行前目标消失取消，以及真实模型采样 → shard 往返 → PPO 概率复算。另验证混合规则 shard 在更新前被拒绝。

本次验证使用本地测试场景，未调用正在训练的远端引擎；启用后的实际对战收益仍需在后续独立评估中验证。
