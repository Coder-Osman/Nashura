## 结论

下一步优先优化学习器的跨轨迹合批、重复编码和进程初始化。采集侧优先验证按需构造观测，其次才是原生输出格式与集中 GPU 推理。现有无跨决策神经状态的设计恰好允许独立观测合批，这些优化无需加入 LSTM 或改动策略网络。

已经测得：602 条真实观测的 FP32 编码前向，原按轨迹切分的第二遍耗时 1.087 秒，跨轨迹每批 128 条为 0.255 秒，约 4.26 倍吞吐。该测试仅覆盖预打包后的编码器前向，不代表完整 PPO 或整轮获得相同比例提升；尚未验证合批后的动作头、梯度与优化器更新一致性。

## P0：学习器跨轨迹合批与复用输入

现有 `native_runner/training/event_ppo.py` 的 `_encode_rows` 每次重新 `_stack_frames`，补齐可变维度，再逐张量传 GPU。preflight、value 预计算、梯度更新、更新后 KL 都重复这条路径。

第 192 轮有 3,970 条决策、216 条双方轨迹。按轨迹、每段最多 32 条的切分生成每遍 220 个 batch，平均仅 18.05 条；四遍共 880 次编码调用。

同一组历史数据的离线微基准，16 个 shard、602 条观测、cuda:1、FP32，每种两次前向：

| 分组方式 | batch 数 | 平均行数 | 前向第 1 / 2 遍（秒） | 打包与传输（秒） | 观测到的峰值显存（MB） |
|---|---:|---:|---:|---:|---:|
| 原按轨迹，最多 32 | 32 | 18.81 | 1.319 / 1.087 | 0.376 | 210.6 |
| 跨轨迹 32 | 19 | 31.68 | 0.674 / 0.654 | 0.320 | 210.8 |
| 跨轨迹 64 | 10 | 60.20 | 0.398 / 0.385 | 0.251 | 278.3 |
| 跨轨迹 128 | 5 | 120.40 | 0.289 / 0.255 | 0.233 | 683.7 |

各组 value 与原分组最大绝对差小于 8.35e-7。固定顺序、两次重复、样本规模有限；显存数据不含训练反向图，不能直接作为完整训练的显存预算。

建议先支持 64/128 条独立观测合批，用真实反向测试选择大小；对实体数、关系边数差异明显的数据再考虑按规模分桶，避免大 batch 的 padding 抵消收益。打包后的输入按本轮生命周期缓存，四遍复用；控制 GPU 缓存上限，必要时分块。

必须保持：GAE 按各自轨迹计算；动作、mask、温度、旧概率和优势逐行对齐；全批损失按有效行加权；当前每轮一次 optimizer.step 不变。跨轨迹合批不意味着增加 PPO 更新次数。

## P0：复用 preflight 的 value，减少同步

用第 191 轮权重和第 192 轮完整历史数据，在闲置 cuda:1 做了一次独立内存更新；保存函数仅内存序列化，没有写训练 checkpoint。

| 阶段 | 耗时（秒） |
|---|---:|
| 导入 torch 与相关模块 | 3.91 |
| 加载 checkpoint、构建模型与静态资源 | 16.02 |
| 读取轨迹 | 8.31 |
| 更新前全量概率校验 preflight | 15.70 |
| PPO 更新合计 | 66.19 |
| 其中：GAE 所需 value 重算 | 12.33 |
| 其中：GAE 优势计算本身 | 0.76 |
| 其中：更新后全量 KL | 13.81 |
| 内存序列化 | 0.70 |

主流程总计 108.75 秒，另加导入 3.91 秒。表中的“其中”是嵌套计时，不能再次相加。正式运行约 140 秒的更新校验归档与此离线测试不是完全相同环境；差额包含外部验证、归档及其他进程开销，尚未分别测量。

preflight 已经产生同一权重的 value，却没有交给 GAE 使用。当前无状态、dropout=0，可以在校验通过后缓存 detached value，复用它来计算优势，候选节省范围是此次 12.33 秒的重算。实施时要验证 train/eval 输出一致，并且 preflight 到使用缓存之间没有 value warmup 或其他参数更新；存在 warmup 时必须使缓存失效。

每个小 batch 的统计又多次 `float(tensor)`、`.cpu().tolist()`，造成 GPU 与 CPU 同步。损失、熵、ratio、clip、KL 等可在 GPU 上累计，到阶段结束再取回。preflight 的异常行定位、各动作头误差、非有限值拒绝等诊断继续保留，可集中回传后在 CPU 整理。

## P1：常驻 learner、合并导出、简化重复模型构建

Python collector 已常驻，但 learner 仍每轮重新起进程、导入依赖和构建模型。上面的 3.91 + 16.02 秒表明这条路径仍值得优化，实际可节省多少须做热运行验证。

远端 `fleet_runtime.py:update` 更新后又起独立 Python 进程，同时加载子 checkpoint 与父 checkpoint，构建两份完整模型。父模型在这一步主要用于读取父 hash、迭代数和 optimizer_steps。可改为读取父 payload 并核验身份，子 checkpoint 仍保留落盘回读、strict load、参数有限值及计数校验；不删除完整性检查。

推理 artifact 导出也每轮另起 Python 进程，正式日志测得约 5.59–5.64 秒。可由常驻 learner 在训练 checkpoint 保存且 hash 确定后导出，继续保留独立 artifact hash、源 checkpoint hash 和契约身份。

常驻化应先覆盖完整轮次恢复、异常退出与 AdamW 状态恢复，再切换正式流程；内存中的模型不是归档替代品。

## P1：环境按需构造双视角观测

540 局平均每局：环境 step 29.39 秒、模型推理 9.94 秒、特征处理 0.80 秒。环境内部 channel 总计约 15.68 秒，其中 receive 14.48 秒、decode 1.19 秒。channel 是环境 step 的子计时，不能相加。

约 85.2% 的 step 没有 event/wake 决策触发；但 `BattleEnvV1.step` 仍返回 `observe_dual` 的完整观测，涉及实体、塔、双方玩家和 action mask 等构造。当前已有同场景缓存，仍需通过函数级计时确认缓存命中率与剩余热点；环境耗时减 channel 耗时的差值也不能全部当成观测构造。

建议分开“引擎推进与公开事件状态更新”和“模型需要的完整观测构造”，后者按需物化。正在执行的计划、合法性检查、奖励、终局、phase 和公开 tracker 必须继续正确推进。WAIT 路径当前也先取 action_mask 再判断 wait，可在确认原合法性条件后增加轻量路径；mask 已有缓存，收益需要测量。

验收需要同 seed 的事件序列、决策时刻、mask、公开 tracker、奖励与终局对齐。保留 30 tick 推进上限和事件消费规则。无决策步骤不等于可以跳过全部环境处理。

## P1：批量缓存核验与轮间计时

本次已观察到 34.78 秒轮间停顿。建议把待清理 checkpoint 的归档路径和预期 hash 汇成一个请求，在 `.37` 单次执行批量核验，返回逐文件结果，再按原规则处理已验证的本地缓存。保留当前权重、恢复所需权重和初始权重；失败项留存。

增加 archive、cleanup、export、load、preflight、GAE、backward、post-KL 等独立计时；同时记录相邻 iteration-start 间隔，使磁盘维护成本进入真实吞吐统计。此项是建议，本轮没有触发额外清理。

## P2：原生输出格式、集中推理与长尾

每局 channel 平均响应约 54.13 MB、221 批。默认 capture_mode 是 JSON，代码已经支持 zlib-json 和 compact。receive 计时包含引擎计算、原生 capture/序列化与传输等待，不代表纯网络；当前通道已是持久 TCP、TCP_NODELAY 和 step_until_event。

优先在独立端口比较 JSON、zlib-json、compact 的总耗时、CPU、字节数，并验证事件完整性、观测字段、mask 和 tracker 等价。压缩会增加引擎端 CPU，不能仅凭体积判断收益。

现有每个端口独立 CPU 推理，平均每局约 10 秒。之后可测单机共享 GPU 服务，把同时 ready 的观测组成小批；保留逐局 RNG、权重版本与动作/log-prob 配对。微批等待延迟和 IPC 也有代价，当前 learner 合批证据更充分，优先级更高。

## 推荐实施与验收顺序

1. 学习器跨轨迹合批、输入复用、preflight value 复用与统计合并。固定历史样本对比 log-prob、value、GAE、梯度、一次 AdamW 更新后的参数及 KL；遇浮点归约差异用明确容差，不声称逐位相同。
2. 常驻 learner 与推理导出，优化父 checkpoint 验证；批量核验缓存并补齐计时。保留断点恢复与落盘完整性。
3. 环境观测按需构造与 WAIT 路径。用固定真实对局验证语义和吞吐，再考虑协议格式和集中推理。

目前没有实测完整改造后的整轮收益，不承诺整轮倍速；多 GPU DDP、torch.compile、FP16、扩大 tick、异步旧策略样本均不作为本次首选。
