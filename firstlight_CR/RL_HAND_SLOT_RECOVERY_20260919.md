# 第 535 轮采集故障修复与恢复

任务：从第 251 轮追加训练至 551 轮，随后执行 551 对 251、351、451、501 的固定权重评估，每组 540 对换边局。

## 根因

2026-09-19 07:05（北京时间），第 535 轮采集在 `.41:29090` 失败，同一随机种子 `2234459013` 重试三次均出现手牌与请求卡牌不一致。该轮其余 107 局正常；学习器尚未更新。最后完整且已归档的权重为第 534 轮：

`32d783821d8fc9ca29e951279268989e243785fa498c8966506f12c9f9bf8f13`

原代码、原权重和原种子的独立复现，在 tick 1105 报出同样错误：

| 手牌列表下标 | 真实槽位 | 卡牌 ID |
|---|---|---|
| 0 | 1 | 28000007 |
| 1 | 2 | 27000009 |
| 2 | 3 | 26000015 |

槽位 0 暂时为空，FAIR 观测中的 `hand` 是按真实槽位排序后的紧凑卡牌列表。旧执行代码用 `player.hand.index(card_id)` 得到列表下标 2，错误地向真实槽位 2 发出卡牌 26000015 的命令；该卡实际位于槽位 3。观测元数据已有正确的 `hand_slot_by_card` 映射。

决策掩码也存在相同假设：使用 `enumerate(player.hand)` 关联落点和可用性，并按原始列表次序读取费用。这些都需要按真实槽位关联。

## 修复

- 统一使用当前 FAIR 观测的 `hand_slot_by_card`，保留换牌过程中的空槽位。只对没有槽位元数据的旧测试夹具保留连续列表约定；显式映射缺失或非法时直接报错。
- 延迟出牌在执行时重新读取真实槽位；采样掩码和费用也按真实槽位绑定。
- 同步修复逐 tick 参考运行器。
- 在五台机器上建立独立 `collector-handslot-code`，仅应用槽位补丁。为 CPU 固定权重评估建立独立 `evaluation-handslot-code`，使用同一修复。

模型权重、无状态输入、PPO 算法、训练超参数、轮数、种子和评估对阵保留。生产补丁基于远端实际代码生成，未把本地其他功能差异带入。原快照保留，所有修改文件通过临时文件原子替换，避免修改硬链接的历史文件。
