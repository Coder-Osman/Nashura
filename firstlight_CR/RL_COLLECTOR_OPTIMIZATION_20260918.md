# 常驻采集流程审查

审查对象：`.34` 的 `runs/event-residual-v3-30r-20260918` 实际代码快照与第 172、179、183 轮日志。没有修改运行中的训练代码、参数或进程。

## 结论与测量

原生引擎常驻，但 Python 采集器不常驻。`fleet_runtime.py:rollout_host` 每轮启动 108 个 Python 进程，每个进程加载一次 checkpoint、初始化语义目录，只运行一局便退出。每台主机还逐个端口串行启动 rsync 拉取结果。

第 172–179 轮平均采集/汇总 161.69 秒，更新/校验/归档 142.96 秒，总计 304.65 秒。只优化采集有收益上限，更新阶段仍约占全轮 47%。

实际抽查：

|---|---:|---:|---:|
| 172 | 169.11 秒 | 26.3–28.8 秒 | 11.5–15.3 秒 |

| 183 | 156.68 秒 | 26.7–29.0 秒 | 11.6–15.1 秒 |

开始偏移用保留的日志 mtime 减去对局 elapsed_s，再减本轮开始时间估计；含任务分发、0.5 秒逐槽错峰、初始化、reset，以及少量输出尾部时间。跨主机时钟偏差也可能影响该估计，不能全归为模型加载。上述 3 轮采集均无重试。每机每轮日志与压缩轨迹总计约 1–2 MB。

在 `.34` 单独运行一次单线程 CPU 只读基准，未连接或占用任何引擎端口：

- 导入 torch 与模型/factory 模块：4.028 秒。
- 首次构建 `production_semantic_bundle()`：13.137 秒。
- 语义目录缓存后完整 checkpoint 加载：2.274 秒。
- 将已在内存中的 state dict 复制到现有模型：0.031 秒。此数不包含文件读取、反序列化和校验，不能当作完整换权重耗时。
- checkpoint 119.94 MB，其中模型张量 42.34 MB；采集器也加载并持有了不需要用于推理的 AdamW 状态。

## 优先级 1：跳过最终会丢弃的模型推理

远端 `code/tools/event_rl_rollout.py:390–410` 先 encode/select_action，之后才检查 `legal.decision_ready`，窗口未就绪时直接丢弃结果。

- 第 179 轮：3,745 个记录决策，3,051 次未就绪丢弃；共 6,796 次模型推理，44.9% 最终没有形成决策。
- 第 183 轮：3,821 个记录决策，3,099 次未就绪丢弃；占 44.8%。

将检查前移到模型 forward 之前；公开信息 tracker 与 tensorizer 的必要更新仍保留，原有 pending plan、奖励累计和轨迹闭合语义保持。跳过动作采样会改变随机数消耗，因此要明确每局/每方的随机数规则，不能声称旧 seed 下整局轨迹逐项相同。校验新的 behavior log-prob 与 PPO 重放一致、非法动作数为零、轨迹完整，并比较固定测试输入的输出。

这项减少约 45% 的 forward 调用，不等于总耗时下降 45%；引擎推进、观测解码和特征构造仍有开销。

## 优先级 2：持久 Python worker

每个已有端口保持一个 Python worker，首次初始化模型、语义目录与静态资源；轮次之间接收任务并严格加载新权重。第一版维持现有端口分工和每轮 108 局，不同时重做调度与训练算法。

任务需要明确 iteration、checkpoint SHA、契约 SHA、seed、输出目录。worker 只在上一局完成并释放 session 后接收新任务；加载确认全部完成后再开始本轮。进程出错只重启对应 worker，并按原 seed 重试。

跨局继续重置环境、tracker、tensorizer、plans、recorder 与随机数状态。进程常驻不意味着模型拥有跨决策记忆。当前代码已有多局 reset/rebind 后 1 tick priming 分支，常驻化需要专门覆盖第二局及换权重后的行为，避免引入额外决策或未记录奖励。

逐槽 0.5 秒错峰可以保留在第一次启动；常驻进程之后无需每轮重做完整启动错峰。静态 manifest 在不可变代码快照初始化时校验，每轮仍核验任务与权重身份。

## 优先级 3：批量回传与精简推理权重

当前每台远端 18/24 个结果目录串行 rsync，累计 84 次远端拉取/轮。按主机生成成功结果 manifest，一次批量传输成功 shard、summary 和日志，再保留每份 SHA 校验。可选完成一局就后台回传，但 learner 仍等待完整 108 局。

训练 checkpoint 保留完整 AdamW；另外导出模型专用推理文件，将分发载荷由约 120 MB 降至约 42 MB。推理文件使用自己的 SHA，明确绑定源训练 checkpoint SHA 与相同语义契约；禁止混淆两种文件身份或弱化 PPO 对行为策略版本的校验。

## 优先级 4：测量后决定批量推理与 capture 格式

现有引擎数据通道已经是局内持久 TCP，使用 `TCP_NODELAY` 和 `step_until_event=True`；不是每步重新建连接。采集调用未指定 capture_mode，实际默认 JSON。factory 支持 compact，但需要核验观测、事件、mask、公开 tracker 特征与当前训练路径完整一致后才能切换。

先把现有 coordinator/channel profile 写入每局报告（接收、解码、字节数），另加 tensorize、合法 mask、encode、采样、reset、写盘分段计时。现有日志仅给对局总时间，尚不足以认定 JSON 或 forward 是最大瓶颈。

之后可评估本机多个环境共享 GPU 推理服务，积累小批量 ready observations。按 checkpoint 版本分批，返回匹配的动作、log-prob、value，保留独立随机数与 mask。无跨步神经状态使这一设计更简单，但依然需要实际吞吐基准，不能直接假定更快。

## 训练语义与验收

保留 30 tick 推进上限，除非已经独立解决并验证事件缓冲区覆盖问题。保留全部完整终局和 108 局 barrier；不要丢弃慢局来缩短一轮，否则会改变长局样本分布。不要用旧权重预先生成下一轮数据却继续按当前严格 on-policy PPO 使用。

建议先做早退检查、持久 worker、按机批量回传，再做推理文件精简；用独立端口或本轮结束后的同种子集合做基准。启动与回传优化可把每轮节省约 20–40 秒作为待验证目标，约占当前整轮 7%–13%；前移未就绪检查带来的额外收益需分段计时确认。不可将此目标作为已实现加速。
