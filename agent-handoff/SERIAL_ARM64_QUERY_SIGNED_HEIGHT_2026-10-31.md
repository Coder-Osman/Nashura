# ARM64 查询高度合并比较实验（2026-10-31）

状态：首轮和不变构建反向case顺序确认均通过真实正式对照与主机独立复算；
固定四输入的增量方向一致，整体目标继续，候选默认关闭。

## 动机与最小实现

当前组件组合的双轮真实profile已定位空间查询为第一热点，占测量窗口叶样本
18.54%–22.66%；其中cell循环占查询样本72.75%–79.55%。本实验只审查该真实
warm调用链，不重建system_server、SurfaceFlinger、GPU/EGL、Display或其他外围服务。

原块 `0xf34c6c..0xf34cb8` 在width拒绝之后先用TBNZ拒绝负y，再加载32位height、
有符号比较height与y。候选用LDRSW将height符号扩展至64位，再用
`CMP X9,W27,UXTW`与零扩展y作64位有符号比较。对所有32位height/y：

`signed32(height) > uint32(y)` 等价于
`signed32(y) >= 0 && signed32(height) > signed32(y)`。

因此在普通有效grid上合并一条条件分支。width读取与拒绝保持原位置，后续cell、
count、结果次序、对象过滤、visited写入/清理与扩展append保持原函数；没有维度缓存。
原76字节整体guard，移动后的所有跳转重新编码并核对原出口；入口与reject落点
guard。RW后RX、刷新指令缓存，仅改一次性进程，不改磁盘原libg。

与旧pair-load实验不同，本候选保留width先行读取和单独height读取；它不启用
旧pair-load、grid展开或52点getter。复用当前`hot-distance-component-v1`作为
直接基线；新增`query-signed-height-v1`与显式组合
`hot-distance-component-height-v1`均默认关闭，组合要求七个有序安装标记。

## 适用边界与验证

负y现在读取height，故要求完整有效普通内存grid；MMIO/volatile、不完整或故障内存、
信号/异步观测不在等价范围。拒绝路径w9为dead，NZCV在原`0xf34c60`的CMP
被覆盖；接受路径height/y都在非负有符号范围，64位与原32位比较的活状态一致。
直接入口审计扫描全部可执行PT_LOAD的对齐immediate branch，唯一外部入口
`0xf34c58 -> 0xf34c6c`。这不证明任意间接目标，保留固定构建/已审计调用边界。

真实ARM64 harness运行原始块和安装后的候选：192424例，符号边界、负y、空cell、
count边界、三出口和保护页通过。新harness重放实际reject落点的CMP/ADD/B.EQ，
验证其覆盖flags而不靠猜测。局部harness和全宽predicate工程测试不替代真实完整局。
完整函数范围由固定ELF/FDE核对，原libg SHA继续为

## 测量方案

固定Fusion Ubuntu ARM64，2vCPU/6144MiB、affinity[0,1]，kernel6.8.0-138-generic。
相同libg/资源/DEX、A/B两卡组、seed1/7和52/51/22/19条固定非空动作。先由同一
新observer对原始、当前组件组合、新候选组合各四输入运行，逐帧serializer payload
与已观测状态比较。12完整局和主机独立原始复算通过，共34047帧，
不扩展为未序列化全部内部状态等价。

正式每case串行ABBA/BAAB八进程，216局/进程，剔16warmup，总32批/6912局，
6400测量局。计时窗口仅warm step loop，排除启动、首次加载、reset及终态校验。
每16tick抽样，相位逐局轮转。关闭perf/Frida/REA/Ghidra/strace、逐tick快照、
详细状态、阶段/线程/生命周期诊断。工程测试与编译在正式前结束，计时中暂停。

报告必须列批次中位耗时、聚合ticks/s、采样p50/p95/p99和两block方向；以批次
为比较单位，批内局不作IID。主机频率、热状态和VM调度未锁定，硬件PMU
cycles/cache仍缺失；不把软件profile或局部harness解释为因果加速。
