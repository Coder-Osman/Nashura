# ARM64 网格清理循环展开（2026-10-31）

状态：指令对照、12 个完整局门及 32 批串行计时经主机复算通过。增益不一致，候选继续默认关闭；整体目标继续进行。

## 动机与语义

基于 8d8abd111e2594bad9a61ebd90e07cf91c5792ca 的真实 warm-step 采样，
原始 +0xf34864..+0xf348d4 清理函数占四组测量窗口样本的 1.96%–3.01%。
没有省略清理、引入缓存或重新建立外围 Android 服务。本候选只把每次两项的
循环展开为四项，保留逐 pair 的指针读取和四字节计数清零顺序。

- 原始宽高以 32 位模乘计算，再按 signed int32 判断；非正数只清 grid+0x40。
- 正数时保留每次两个指针读取、两个 cell+0xc 写零；奇数尾项单独读取一个指针。
- 不提前读取下一 pair，不扩大 store 宽度；重复 cell 的写入次数和顺序保留。
- 不访问原函数 112 字节范围外的指令；尾部填一条 NOP。完整原始字节校验后
  才在首局前 RW→RX 安装，刷新指令缓存。默认关闭，安装失败拒绝 disposable task。
- 仅改 caller-saved 临时寄存器与 NZCV；SP、LR、callee-saved 寄存器保持。
  直接 BL 扫描找到 +0xf2ff08；后续指令不读被改临时寄存器或旧 NZCV。
  未声称穷尽所有间接调用者，故保留标准 ABI 与串行 Mainloop 的适用边界。

寄存器约定核对 Arm AAPCS64 2025Q1 §6.1.1。官方文档 URL 与下载 SHA、
精确 ELF、原始/替换字节 SHA 记录于机器摘要；完整第三方 ELF 与资源不随报告发布。
异常 PC、采样地址及故障现场寄存器可能不同，不声明诊断现场等价。

## 两个显式候选

grid-clear-unroll-v1 只替换上述清理函数；hot-distance-grid-v1 显式组合已经验证的
hot-distance-v1 与清理候选。后者逐项要求原 11 getter、2 distance、组合和 grid
安装标记，仍默认关闭。正式比较使用同一新 observer 的 hot-distance-v1 与
hot-distance-grid-v1，避免把 observer 构建差异计作增益。

## 验证方法

保持既有 Fusion ARM64 Ubuntu 2 vCPU / 6144 MiB、系统配置、资源、原始 libg、
DEX、两卡组、seed 1/7 与固定非空动作。无并发，冻结部署和 main 保持原样。

独立 ARM64 harness 执行原始与替换指令，共 24107 组：计数 0..4099、随机宽高、
负数与模乘溢出边界；随机重复 cell，指针表尾与最后 cell 字段紧邻 PROT_NONE。
校验完整 grid 与 cell 内存，没有用 C 仿真结果替代真实指令执行。

四组各运行原始、新 observer 的 hot-distance-v1 与组合候选，共 12 个完整局，
与既有 full-original 的全部 serializer 帧及已输出关键状态逐项比较。
计时与正确性分开：每组八批 ABBA/BAAB，每批 216 局、剔除 16 warmup，
共 6912 局 / 6400 测量局。每 16 tick 确定性轮转抽样时延，整段 warm-loop 吞吐；
初始化、reset 与终态序列化在计时窗外。

正式计时关闭 perf、Frida、REA/Ghidra、strace、逐 tick 快照、详细状态、阶段与
线程诊断。工程测试在 guest launch 前结束，运行中暂停；该措施不证明主机温度、
频率、调度或所有其他负载隔离。主机验证器独立解压并复算计划、退出码、动作数、
全部帧、终态及 batch 统计，不依赖 guest 保存的成功布尔值。

## 准备失败记录

首次 guest 准备脚本退出 1，未保存 traceback，不将具体原因写成已确认事实；
随后只读检查发现 guest 未安装 cc。再次执行同一准备脚本因目录已存在退出，
FileExistsError 日志保留。沿现有 Android30 NDK 在主机编译 harness，经同一最小
namespace 在 ARM64 guest 运行通过；没有安装新编译器或修改系统配置。
主机两次脚本生成/转义语法错误在执行前拦截，未启动 workload，随后修正。
主机对 launch 转义格式曾作额外预检；实际退出记录为标准零退出加换行，
最终验证器沿用严格零退出检查。
