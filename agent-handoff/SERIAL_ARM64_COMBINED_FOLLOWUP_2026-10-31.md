# ARM64 组合候选独立复测与串行稳定性（2026-10-31）

状态：八个新完整局全帧门、32 批独立交错计时和四组共 49536 局同进程串行稳定性均通过；主机从原始归档逐项独立复算。整体温热运行时目标继续进行。

## 固定输入与运行边界

基于 9588927e2919e4b5440c619b51de8bec7e6cae7e，沿用同一真实 ARM64 libg、
资源、两卡组及 seed 1/7 固定非空动作。Fusion ARM64 Ubuntu 保持 2 vCPU /
6144 MiB，未改系统配置，没有并发测试或新增外围 Android 服务。组合候选
hot-distance-v1 默认关闭，本轮不修改 native observer 或 DEX。
macOS 上的宿主进程为 Fusion vmware-vmx；该 ARM64 Linux 路线没有 QEMU
指令翻译层，仍依赖现有 ELF/Bionic/ART，不是 macOS 原生移植。

先完成全部主机工程检查并确认进程退出，再启动 guest；时间界限和进程记录
保存为私有证据。运行期间不再启动工程测试。该边界仅排除本轮工程测试重叠，
不等于主机完全空闲、固定频率、固定热状态或无 VM 调度干扰。

## 磁盘与证据保存

预检 guest 根盘余约 20 MiB；精确核对旧距离阶段归档及八份快照 SHA 后，
将八份 guest raw 快照无损 gzip，逐份解压 SHA 一致后回收 raw 副本，释放
69059648 字节。原始主机归档和已复算解包副本仍保留，未清理输入或失败证据。

新增显式 --compress-stdout：引擎继续直接写普通日志，正常或异常退出码先
记录，之后才压缩。仅当 gzip 解压 SHA 与原文件一致时回收 raw。压缩损坏或
异常引擎退出均拒绝验收并保留证据；默认输出路径不变。压缩不在 warm step
窗口内运行，不增加输出管道或 profiler。新快照也在完整局退出后无损压缩。

## 测量设计

四组每组八个新进程，顺序 original / combined / combined / original /
combined / original / original / combined；每批 216 局，剔除 16 局预热，
总计 6912 局、6400 测量局。统计单位为四个进程批次，不将批内重复局视作 IID。
每 16 tick 轮转相位采样，关闭逐 tick snapshot、详细观察、阶段/线程资源诊断
和 profiler。终态仍逐局验证；完整局全帧门与计时门分开。

随后每组使用一个已初始化的组合候选进程，24 个串行 task × 516 局，共
12384 局/进程、四组共 49536 局。每个 task 仍受 120 秒 native 等待上限约束，
外层进程最多 600 秒，不更改既有上限。检查唯一 create、固定 Mainloop TID、
批间时钟顺序、终态身份、退出及 RSS 样本；它是有界观察，不等于 24 小时稳定性。
