# ARM64 headless 空间查询调用者静态审计

## 结论

对与串行 profile SHA 一致的 ARM64 `libg.so` 继续进行只读静态反汇编。调用点
`+0xf5d9d8` 将一个二维坐标指针和一个从对象字段计算出的范围值交给
`+0xf34afc`；该包装器读取两个 32 位坐标，再转入 `+0xf34b3c`。后者以固定点
坐标的 `2^10` 缩放值计算 x/y 格范围，遍历 row-major 网格桶，对候选对象读取状态、
使用访问标记、执行虚调用与条件过滤，并维护结果集合。

此处可以把它收敛为通用的“空间格候选查询/广相候选过滤”实现形态。现有材料不足以
确认它用于碰撞、寻敌、范围效果或其他具体玩法逻辑。包装器至少有四个直接调用点，
其上层函数也有三个直接调用点，进一步说明该实现可被多个上下文复用。profile 中
`Mainloop` 线程的热点归属保持原结论；本轮静态分析没有新增动态调用链证据。

## 静态证据

- 输入 ELF SHA-256：`110aa2b5cac391c498645e072b0d88729428c2c2845e7e2737ca8ee979059783`；
  Build ID：`90e6f351f0dec4a28b494c3812d2629fd45d5a83`。
- GNU EH frame 索引给出查询主体 `+0xf34b3c` 至 `+0xf35064`，调用方函数
  `+0xf5d7e0` 至 `+0xf5deb0`；profile 中的调用指令位于 `+0xf5d9d8`。
- `+0xf34afc` 读取坐标指针的前两个 word，并将它们作为中心 x/y 传给查询主体。
- 查询主体计算中心坐标加减范围值，再算术右移 10 位得到格坐标；网格宽、高及桶表
  分别从网格对象字段读取，桶下标使用行优先乘加。
- 候选遍历访问对象 `+0x0c` 状态、`+0x50` 访问标记及 vtable `+0x10`、`+0x178`
  虚调用。回调和字段语义均未命名。
- `+0xf34afc` 的直接调用点为 `+0xf329ac`、`+0xf5d548`、`+0xf5d9d8`、
  `+0xf67930`；`+0xf5d7e0` 的直接调用点为 `+0xf19c28`、`+0xf24a64`、
  `+0xf61504`。

机器可读摘要见[证据文件](serial-arm64-query-caller-audit-evidence-20261030.json)。

## 边界与后续

本轮只做本地静态读取与反汇编，没有启动 guest、没有执行 replay、没有测并发或性能，
也没有修改或分发第三方二进制。函数符号、回调语义、动态调用者身份、多 seed/卡组
覆盖和优化收益仍未确认。当前证据不支持引入战斗行为改动或宣称已完成优化。

下一步应在串行固定 workload 中被动捕获相关虚调用的 receiver/vtable 身份，并与
已知战斗对象做只读关联；保持 headless 最小依赖边界，只有真实战斗路径证据才继续
解释服务或子系统依赖。
